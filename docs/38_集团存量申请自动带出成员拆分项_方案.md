# 集团存量申请自动带出成员拆分项 —— 详细方案

> 版本:2026-09-07 编写 | 状态:待确认
> 一句话:让「集团客户做存量调息申请」时,像单户客户一样,选完授信协议后系统自动把**协议名下每个成员各自**的数仓拆分项列出来,经理勾选即生成分项,不用逐成员手输。
> 涉及面:后端(数仓查询 + 1 个接口 + 提交校验)+ 前端(`loan.vue` 协议联动与成员拆分项渲染)+ 测试数据。

---

## 0. 先讲清楚三个词(不然后面看不懂)

| 词 | 意思 | 例子 |
|---|---|---|
| **存量调息申请** | 客户对**已有**的授信,想申请换个利率(通常是降利率)。申请按"一条条已有的授信明细"来做,每条填上"想调到的利率"。 | 旧抵押贷款 2000 万、利率 4.35%,想调到 3.8% |
| **授信协议 / 集团授信** | 一次批复给的一笔总授信。集团客户名下可能是"集团授信协议",里面是给整集团批的一笔总额。 | 集团授信协议 GC-2026-001,批复 5000 万 |
| **拆分项** | 数仓把"授信"按**担保方式**拆成的一条条明细。每条 = 什么担保(抵押/保证)+ 多少钱 + 原利率 + 到期日。**存量调息就是逐条对拆分项做的。** | ① 抵押 2000 万 4.35%;② 保证 1000 万 4.65% |

**成员** = 组成集团的一家家公司。集团授信的钱是分到各成员头上的(每家一个"成员额度"),各成员名下再有自己的拆分项。

## 1. 业务背景:为什么要有这个功能

### 1.1 单户客户(一个独立公司)今天已经能做这件事

客户经理给**单个对公客户**做存量调息,界面流程是:

1. 客户信息区选客户 → 选"业务类型 = 存量调息(EXISTING)"。
2. 界面出现「授信协议」下拉 → 系统从数仓 `dw_credit_agreement_snapshot`(授信协议快照)带出该客户所有授信协议,经理选一份。
3. 界面上方出现一条**工具栏**:「数仓拆分项共 N 项,当前协议"XXX"名下 M 项」+【带入当前协议拆分项】按钮。
4. 经理点按钮 → 系统把**这份协议名下**的拆分项(`dw_credit_split_snapshot`)逐条生成"分项卡",每张卡自动填好:担保方式、授信金额、原利率,连**担保物/保证人明细**都从 `dw_credit_split_measure_snapshot` 带出来。
5. 经理在卡上填「申请利率」「测算利率」→ 提交。
6. 后续审批、决议全程带着这些拆分来源(每个分项落一个 `source_split_no` 溯源、防重复提交)。

> 关键机制:**单户拆分项 `dw_credit_split_snapshot.credit_no` = 授信协议号**(2026-09-03 #473 确立)。所以前端"选哪份协议,就只带 `credit_no == 该协议号` 的拆分项",准确、不串协议。

### 1.2 集团客户今天做不了这件事

集团客户进申请页 → 选业务类型 = 存量调息 → 也有协议下拉(2026-09-03 #485 已把**集团授信行** `dw_group_credit_snapshot` 直接当协议用)。**但**,集团协议下挂的是**很多成员**,每个成员名下才有拆分项。现在系统:

- 前端选完集团协议后,**不会去拉"各成员名下的拆分项"**(`loan.vue` 里 `creditSplits` 只在单户 `business-view` 时填充;集团 `queryGroup()` 不填充它);
- 所以工具栏不出现,经理只能对着纸面台账,**逐个成员手动加分项、手输金额和原利率** —— 又慢又容易抄错。

### 1.3 目标

集团存量调息时,经理**选一份集团授信协议**,系统自动把**该协议下所有成员各自的全部拆分项**拉出来、按成员分组展示、每条标注属于哪家成员;经理可勾选、一键带入,生成的分项天然归属到对应成员名下。提交/审批/决议与现在完全一致(只多了一开始的"自动带出")。

## 2. 集团与单户的数据怎么串(核心一张图)

数仓三张表,靠编号层层挂:

```
dw_group_credit_snapshot            集团授信快照(≈集团协议)
  group_credit_no = GC-2026-001
  group_no        = G001            ← 集团客户号
  approved_total_amount = 5000      批复总额
        │  (一个集团协议下面,挂 N 个成员额度)
        ▼
dw_member_credit_limit_snapshot     成员额度快照(每家成员一条额度)
  member_limit_no    = ML-A001       成员额度号 ★
  group_credit_no    = GC-2026-001   ← 挂在哪份集团协议下
  member_customer_no = A001          成员客户号 ★(这家公司是谁)
  allocated_amount   = 3000          这家成员分到多少
        │  (一个成员额度下面,挂 N 条拆分项)
        ▼
dw_credit_split_snapshot             授信担保拆分项(要调息的明细)
  split_no          = SPLIT-A1       拆分项编号
  cust_no           = A001           客户号(谁家的拆分项)
  credit_no         = ML-A001        ★★ = 成员额度号(2026-09 契约拍板)
  guarantee_type    = MORTGAGE       担保方式
  split_amount      = 2000           拆分金额
  original_rate     = 4.35           原利率
  split_status      = EFFECTIVE      有效
```

### 为什么必须用「成员额度号」串,而不能用别的

| 候选关联键 | 结论 | 原因 |
|---|---|---|
| 拆分项 `credit_no` = **集团授信号**(GC-2026-001) | ❌ 不行 | 集团授信是整集团一笔总额,没有按担保拆的明细粒度;拆分明细是**落在各家成员名下**的 |
| 拆分项 `credit_no` = **成员授信协议号** | ❌ 不行 | 集团切分授信**没有"成员协议"这一层**(成员只有"成员额度") |
| 拆分项 `credit_no` = **成员额度号** `member_limit_no` | ✅ **采用** | 数仓里唯一能表示"这条拆分明细挂在某成员额度下"的键,且恰好能一路反查到集团协议 |

**取数路径(正式)**:选集团协议 `GC-2026-001`
1. `dw_member_credit_limit_snapshot` 里取 `group_credit_no = 'GC-2026-001'` 的所有行 → 得到该协议全部 `member_limit_no`(如 ML-A001、ML-B001、ML-C001);
2. `dw_credit_split_snapshot` 里取 `credit_no IN (ML-A001, ML-B001, ML-C001) AND split_status='EFFECTIVE' AND data_dt = 最新批次` → 得到整份协议下所有成员的全部拆分项。

这一步是"按所选集团协议**整单带**"—— 一家集团如果名下有多份集团授信协议,只带**当前选中这份**协议下的成员拆分项,不带别的协议的(防止串协议,和单户 #473 同一原则)。

### 3.4 前端缺的

1. `creditSplits`(拆分项数组)在**集团**模式下没被填充 —— `queryGroup()` 只填协议,不填拆分项;
2. `agreementSplits`(当前协议名下拆分项的过滤,L1957)是**单户口径**:按 `sp.creditNo === 当前协议号` 过滤 —— 单户 `credit_no=协议号` 成立;**集团 `credit_no=成员额度号`**,按协议号过滤会全空,必须换成集团自己的过滤逻辑;
3. 拆分项与**成员**的绑定:单户拆分项不归属成员;集团拆分项必须落到 `memberCustomerNo`,且渲染/带入时不能放错成员页签;
4. 工具栏在集团模式下的展示与文案(单户文案含"当前协议名下 N 项",集团要按协议口径说明)。

## 4. 详细改动方案

### 4.1 后端 A:新增数仓查询方法

**文件**:`backend/ccr-application/src/main/java/com/ccr/application/service/DataWarehouseService.java`

新增方法(与 `creditSplits` 并列,放在「授信担保拆分明细」小节):

```java
/**
 * 集团存量:按「成员额度号集合」取拆分项(最新批次,仅有效)。
 * 契约(2026-09):集团拆分项 credit_no = dw_member_credit_limit_snapshot.member_limit_no;
 * 前端从集团协议 group_credit_no → memberLimitsByGroup 拿到全部 member_limit_no 后调用本方法,
 * 得到该协议名下全部成员的全部拆分项。
 */
public List<Map<String, Object>> splitsByMemberLimitNos(Collection<String> memberLimitNos) {
    if (memberLimitNos == null || memberLimitNos.isEmpty()) {
        return List.of();
    }
    String placeholders = String.join(",", java.util.Collections.nCopies(memberLimitNos.size(), "?"));
    return jdbcTemplate.queryForList("""
            SELECT * FROM dw_credit_split_snapshot
            WHERE credit_no IN (%s)
              AND split_status = 'EFFECTIVE'
              AND data_dt = (SELECT MAX(data_dt) FROM dw_credit_split_snapshot)
            ORDER BY cust_no, split_no""".formatted(placeholders), memberLimitNos.toArray());
}
```

> 说明:`IN (...)` 的成员额度号数量 = 集团协议下成员数,几十条以内,用占位符安全(和现有 `splitMeasures` 同一写法)。

### 4.2 后端 B:新增接口(集团协议 → 成员拆分项,内嵌措施)

**文件**:`GroupQueryController.java`

新增 GET(只读,沿用类级 `@SaCheckRole(customer_manager/admin)`):

```java
/**
 * 集团存量调息数据源:按所选集团授信协议,整单带出该协议下全部成员的全部拆分项。
 * 取数:group_credit_no → dw_member_credit_limit_snapshot 全部 member_limit_no
 *      → dw_credit_split_snapshot 中 credit_no IN (…) 的拆分项(有效、最新批次)
 *      → 每项内嵌担保措施(T22)+ 成员名。供 loan.vue EXISTING + GROUP 模式调用。
 */
@GetMapping("/ccr/groups/{groupNo}/splits")
public R<List<Map<String, Object>>> groupSplits(@PathVariable String groupNo,
        @RequestParam(required = false) String groupCreditNo) {
    if (mergedGroup(groupNo) == null) {
        throw new ServiceException(404, "集团不存在:" + groupNo);
    }
    // 未传协议 → 默认取该集团第一份有效协议(findGroupCredit 现成逻辑)
    Map<String, Object> credit = StrUtil.isBlank(groupCreditNo)
            ? mergedCredit(groupNo)
            : dataWarehouseService.findGroupCreditByNo(groupCreditNo);
    if (credit == null || credit.get("group_credit_no") == null) {
        return R.ok(new ArrayList<>());   // 无集团授信 → 空列表(前端纯手工兜底,不阻断)
    }
    String gcNo = String.valueOf(credit.get("group_credit_no"));
    // ① 该协议下全部成员额度号
    List<String> memberLimitNos = dataWarehouseService.memberLimitsByGroup(gcNo)
            .stream().map(l -> String.valueOf(l.get("member_limit_no")))
            .filter(StrUtil::isNotBlank).distinct().toList();
    // ② 全部成员拆分项
    List<Map<String, Object>> splits = dataWarehouseService.splitsByMemberLimitNos(memberLimitNos);
    // ③ 内嵌担保措施 + 成员客户号/成员名
    List<String> splitNos = splits.stream().map(s -> String.valueOf(s.get("split_no"))).toList();
    List<Map<String, Object>> measures = dataWarehouseService.splitMeasures(splitNos);
    List<Map<String, Object>> result = new ArrayList<>();
    for (Map<String, Object> sp : splits) {
        String sn = String.valueOf(sp.get("split_no"));
        String custNo = String.valueOf(sp.get("cust_no"));
        Map<String, Object> corp = dataWarehouseService.findCorpCustomer(custNo);
        Map<String, Object> row = camel(sp);
        row.put("measures", camelRows(measures.stream()
                .filter(m -> sn.equals(String.valueOf(m.get("split_no")))).toList()));
        result.add(row);   // 保留 cust_no(即 memberCustomerNo);成员名由前端用 memberNameOf 统一解析即可
    }
    return R.ok(result);
}
```

> 需在 `DataWarehouseService` 补一个 `findGroupCreditByNo(groupCreditNo)`(按协议号查集团授信单条,最新批次)——或复用现有 `findGroupCredit(groupNo)` 查不到"指定协议号"时改用 `memberLimitsByGroup` 里第一条;推荐补一个干净的小查询。

### 4.3 前端改动(loan.vue)

#### ① 拉数据:选集团协议后填充成员拆分项

- 新增响应式:`const groupSplits = ref<any[]>([])`(集团协议下所有成员拆分项,含 `custNo`)。
- 在 `selectCreditAgreement(a)`(L1697)集团分支里,拿到 `a.agreementNo`(即集团协议号 `group_credit_no`)后调用新接口:

```ts
async function loadGroupSplits(groupCreditNo: string) {
  if (form.customerScope !== 'GROUP' || form.businessType !== 'EXISTING') return
  groupSplits.value = []
  if (!form.groupNo || !groupCreditNo) return
  try {
    const r: any = await apiGetGroupSplits(form.groupNo, groupCreditNo)  // GET /ccr/groups/{no}/splits?groupCreditNo=…
    groupSplits.value = r || []
  } catch {
    groupSplits.value = []   // 拉取失败不阻断:纯手工兜底
  }
}
```

- 集团模式:`selectCreditAgreement` 里先按协议拉,再清旧行(`L1710` 现有逻辑保留),把返回的分项带入;新增模式 / 无协议时不拉。

#### ② 过滤逻辑:集团用「成员额度号集合」而不是「协议号」

新增 computed(替代集团场景下的 `agreementSplits`):

```ts
/** 集团存量:当前协议名下成员拆分项(拆分项 credit_no = member_limit_no;单户按协议号过滤的逻辑不适用) */
const groupAgreementSplits = computed(() => {
  const agr = currentAgreementNo.value
  if (form.customerScope !== 'GROUP' || !agr) return []
  const nos = (selectedMembers.value || [])          // 成员额度号集合来自所选协议
      .map((m) => groupCreditLimitNoOf(m.memberCustomerNo))
      .filter(Boolean)
  return groupSplits.value.filter((sp) => nos.includes(sp.creditNo))
})
```

> 成员额度号来源:集团 `GET /ccr/groups/{no}/members` 返回里每个成员带 `creditLimit.memberLimitNo`(后端 L118-120 已带),前端 `selectedMembers` 可扩展存 `memberLimitNo`;或干脆在后端接口就把 `custNo` 解析成 `memberCustomerNo`,前端按 `sp.custNo` 与成员号匹配即可(推荐后者,少一层状态)。

#### ③ 渲染与带入:按成员归属

- **工具栏**(L644–647)在集团模式下显示成员拆分项数,文案形如:「集团协议 X 名下成员拆分项共 N 项」,【带入当前协议拆分项】调一个"集团版 selectAllSplits」:
  - 遍历 `groupAgreementSplits`,跳过 `isSplitSelected(sp.splitNo)`;
  - 生成分项卡时**强制归属到拆分项所在成员**:`g.memberCustomerNo = sp.custNo`(而不是当前 `activeMemberTab`),再 `g.sourceSplitNo = sp.splitNo`(溯源、去重);
  - 复用 `splitToGuarantee(sp)`(L1905)带出金额/原利率/担保物。
- **成员页签角标 / 过滤**不动:带入后分项自然落在对应成员 Tab 下(现有 `visibleGuarantees`/`memberTabs` 已按 `memberCustomerNo` 分组)。
- **卡头成员徽标**(L654)、**拆分项徽标**(L656)自动生效,无需改。

#### ④ 提交、校验、审批、决议

- **完全不动**:提交组装(L2591–2652)已带 `memberCustomerNo` + `sourceSplitNo`;`ccr_pricing_item.source_split_no` 溯源、防重(#449)现有;审批详情/决议书按分项展示的现有逻辑全部继承。

### 4.4 边界行为(必须保持一致)

| 场景 | 行为 |
|---|---|
| 集团协议选了但数仓没有成员拆分项 | 返回空 → 工具栏不出现 → 经理纯手工加(现状兜底,不阻断提交)|
| 该集团无集团授信(纯手工补录批复) | `groupCredits` 为空 → EXISTING 前端阻断提示(现有 #485 逻辑),本功能不参与 |
| 切换集团协议 | 重新 `loadGroupSplits(新协议号)` → 清上一协议自动带入的 `sourceSplitNo` 行(L1710 现成)→ 带入新协议拆分项 |
| 集团存量切回新增(NEW) | 现有 L1845 清 `sourceSplitNo` 行逻辑生效,不残留 |
| 拆分项已被经理手动删掉/改过 | 用 `sourceSplitNo` 精确标识与去重(`isSplitSelected`),不会二次带入同一拆分项 |

## 6. 端到端验证清单(验收口径)

1. **造数校验**:`SELECT split_no, cust_no, credit_no FROM dw_credit_split_snapshot WHERE credit_no LIKE 'ML-%'` 能查到上面 3 条。
2. **接口单测**:`GET /ccr/groups/{GROUP001}/splits?groupCreditNo={GC-GROUP001-2026}` 返回 3 条,分别带 `custNo=MEMBER_A/MEMBER_A/MEMBER_B`、`creditNo=ML-GA01/ML-GA01/ML-GB01`,且措施内嵌。
3. **前端 E2E(客户经理账号)**:
   - 新建贷款申请 → 集团客户 GROUP001 → 业务类型=存量调息;
   - 选集团授信协议 → 工具栏出现「…成员拆分项共 3 项」;
   - 点【带入当前协议拆分项】→ 出现 3 张分项卡,A 的 2 张落在 A 成员页签下、B 的 1 张落在 B 页签下,金额/原利率/担保物自动带出;
   - 每张卡填申请利率/测算利率 → 提交;
   - 审批详情能看到分项带成员名 + 拆分项徽标,后续审批/决议正常。
4. **回归(必测)**:
   - 单户存量调息仍按协议带拆分项(#473),不受影响;
   - 集团切到另一份协议 → 拆分项随协议切换、不残留;
   - 无拆分项的集团 → 工具栏不出现,纯手工可提交(兜底不破)。
