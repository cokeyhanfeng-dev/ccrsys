# 审批流程配置操作手册

> 适用对象:系统管理员、配置复核人、业务运营人员
> 目的:讲清 CCR 利率审批系统「审批流靠什么跑、每张配置表怎么用、调整审批人/流程怎么操作」,可照着本节逐表维护。
> 核心原则:**审批流全配置驱动**——机构、用户、部门、利率矩阵、节点指派、节点权限全部通过数据表动态调整,无需改代码;唯一代码硬编码项是**角色码**(`branch_manager`/`dept_gm`/`vice_president`/`committee_member`/`president` 等),新增角色需要改代码,日常调整请勿改动角色码本身。

---

## 1. 审批流全景

### 1.1 两条节点链

| 业务 | 节点链 | 说明 |
|---|---|---|
| **贷款**(对公/个人经营) | `BRANCH_MANAGER`(支行行长) → `DEPT_GENERAL_MANAGER`(部门总经理) → `VICE_PRESIDENT`(分管行长) → `SIX_PEOPLE_GROUP`(六人审批小组) | 逐级上报,链尾为六人小组上会表决 |
| **存款/保证金** | `BRANCH_MANAGER`(支行行长) → `SIX_PEOPLE_GROUP`(审批小组) | 无部门层级,支行过手后直接上会 |

代码位置:`backend/ccr-approval/.../support/RouteChains.java`(`LOAN_CHAIN` / `DEPOSIT_CHAIN`)。

### 1.2 终审岗位(route_code)截断

利率矩阵命中后返回一个 `start_node_code`(即 `route_code`),审批链按此**截断**——链只走到该岗位为止,不再往上。

| 场景 | 截断结果 |
|---|---|
| 矩阵行 `start_node_code = BRANCH_MANAGER` | 链 = `[BRANCH_MANAGER]`,支行行长终审 |
| `start_node_code = DEPT_GENERAL_MANAGER` | 链 = `[BRANCH_MANAGER, DEPT_GENERAL_MANAGER]` |
| `start_node_code = SIX_PEOPLE_GROUP`(或未配) | 全链(贷款走到上会;存款走 `[BRANCH_MANAGER, SIX_PEOPLE_GROUP]`) |

> 简单理解:**利率越低、金额越大,终审岗位越高**。矩阵里那行的 `start_node_code` 决定了这笔申请审批到哪一级。

### 1.3 一个申请怎么走

1. 客户经理提交申请 → 系统按**利率矩阵**匹配出每个分项的审批链(含终审岗位);
2. 分项按链逐级流转:每级先做**节点权限**判定(利率是否在本岗位权限内);
   - 权限内 → 本岗位直接通过(所有分项齐套即整单终审);
   - 超权限 → **ESCALATE 上送**到下一岗位;
3. 到 `SIX_PEOPLE_GROUP` → 上会表决(匿名,≥4 票通过);
4. 部分产品可配置**必经总行行长决策**(`PRESIDENT`)或**强制上会**(`DIRECT_VOTE`)。

### 1.4 审批权限两条线(不要混淆)

| 配置 | 管什么 | 表 |
|---|---|---|
| **利率矩阵** `ccr_rate_matrix` | 决定**审批链/终审岗位**、边界利率(路由) | 第 5 章 |
| **节点权限** `ccr_node_permission` | 决定某岗位**能不能直接批**(权限内/超权限上送) | 第 6 章 |

## 2. 用户 / 角色 / 机构体系

审批人的身份由三张基础表决定:**用户 → 角色 + 机构**。

### 2.1 用户表 `ccr_sys_user`

| 列 | 说明 |
|---|---|
| `username` | 登录名(工号),如 `wangwu` |
| `nick_name` | 姓名 |
| `role_code` | 角色码(决定岗位,见 2.2) |
| `org_id` | 归属机构(关联 `ccr_sys_dept.id`,决定数据权限范围) |
| `status` | `ENABLE` 启用 / `DISABLE` 停用(停用即不再作为处理人) |

### 2.2 角色表 `ccr_sys_role`(9 个角色,勿增删码)

| role_code | role_name | 对应节点 |
|---|---|---|
| `customer_manager` | 客户经理 | —(发起申请) |
| `branch_manager` | 支行行长 | `BRANCH_MANAGER` |
| `dept_gm` | 部门总经理 | `DEPT_GENERAL_MANAGER` |
| `vice_president` | 分管行领导 | `VICE_PRESIDENT` |
| `committee_member` | 审批小组成员 | `SIX_PEOPLE_GROUP` |
| `president` | 总行行长 | `PRESIDENT` |
| `admin` | 系统管理员 | —(全部功能) |
| `auditor` | 审计人员 | —(档案/表决/导出) |
| `config_reviewer` | 配置复核人 | —(参数复核与发布) |

> **角色码与节点一一对应**(代码里 `NODE_ROLE` 映射)。新增/改名角色需改代码,日常只增删角色下的**用户**即可。

### 2.3 机构表 `ccr_sys_dept`

机构用**两级编码**区分:

| 列 | 含义 | 示例 |
|---|---|---|
| `dept_code` | 字母编码(业务展示/关联用) | `HQ` / `GSB` / `CDZH` |
| `org_code` | 数字层级前缀(数据权限按前缀匹配) | `1000` 总行 / `100101` 部门 / `100201` 支行 / `10020101` 网点 |
| `org_type` | `HEAD` 总行 / `DEPT` 部门 / `BRANCH` 支行 / `NETWORK` 网点 | — |
| `branch_code` | 归属支行 org_code(网点用) | — |

**前缀规则**:`1000` 开头 = 总行/部门(`100101`=公司金融部),`1002xx` = 支行,支行码 + `01` = 营业网点。数据权限按 `org_code` 前缀匹配(支行行长只看本支行数据)。

## 3. 节点指派 `ccr_node_assignee`

决定**某个节点由谁处理**(人/角色/部门)。审批时按**四层解析,命中即止**。

### 3.1 表结构

| 列 | 说明 |
|---|---|
| `node_code` | 节点编码: `BRANCH_MANAGER` / `DEPT_GENERAL_MANAGER` / `VICE_PRESIDENT` / `SIX_PEOPLE_GROUP` |
| `assignee_type` | 指派类型: `PERSON` / `GROUP` / `DEPT` / `ROLE` |
| `assignee_code` | 见下表(随类型不同语义不同) |
| `relation` | `OR` 任一(默认) / `AND` 需全员 |
| `delegate_to` | 代理人工号(有效期内替换本人) |
| `delegate_valid_from` / `delegate_valid_to` | 代理有效期 |
| `valid_from` / `valid_to` | 配置有效期(超出则不参与解析) |
| `status` | `ACTIVE` / `INACTIVE` |

### 3.2 四层解析(PERSON → GROUP → DEPT → ROLE,命中即止)

解析时按顺序逐层尝试,**某层解析出非空处理人列表就立即返回**,不再看后续层;全部为空则**不限制**(任何该节点角色用户都可处理)。

| 层级 | assignee_code 写法 | 作用 |
|---|---|---|
| **PERSON** | 用户工号,如 `wangwu` | 指定**某一个人**处理该节点 |
| **GROUP** | 逗号分隔的角色码,如 `committee_member,dept_gm` | 取这些角色下**全部启用用户**的并集 |
| **DEPT** | 两种写法(见 3.3) | 按**机构/部门**取人 |
| **ROLE** | 角色码,如 `dept_gm` | 取该角色下全部启用用户 |

### 3.3 DEPT 层的两种写法(重点)

| 写法 | 语义 | 示例 |
|---|---|---|
| **含冒号** `dept_code:role` | 精确匹配:分项的 `dept_code`(机构部门归属)等于冒号前编码时,取该部门下该角色的启用用户 | `GSB:dept_gm` = 公司金融部下属部门总经理 |
| **不含冒号** `org_code` | 前缀匹配:申请人的机构 `org_code` 以配置值开头,则取该机构及下级全部启用用户(兼容支行/网点) | `1002` = 城东/城西/宜城支行下全部启用用户 |

> **部门分流就靠「含冒号」写法**——同一节点配多行不同 `dept_code:role`,分项按自己的部门归属命中对应处理人(详见第 7 章)。

### 3.4 解析结果的消费

- **待办过滤**:`filterByNodeAssignee` —— 只把解析出的处理人列为待办;
- **审批校验**:`guardNodeAssignee` —— 只有解析出的处理人能操作该节点。

代码位置:`backend/ccr-common/.../core/assignee/NodeAssigneeResolver.java`;消费点:`backend/ccr-approval/.../service/impl/ApprovalServiceImpl.java`。

### 3.5 代理(delegate_to)

某处理人出差/休假时,可配置 `delegate_to`(代理人工号)+ 代理有效期,有效期内该节点由代理人处理,到期自动恢复本人。

## 4. 部门分管行长 `ccr_dept_vp`

分管行长(`VICE_PRESIDENT` 节点)的指派**优先查此表**,命中后不再走四层解析。

| 列 | 说明 |
|---|---|
| `dept_code` | 部门归属: `GSB` 公司金融部 / `SXSB` 授信评审部 / `LSB` 零售金融部 |
| `vp_user_id` | 分管行长用户 id(关联 `ccr_sys_user.id`) |
| `status` | `ACTIVE` / `INACTIVE` |
| `valid_from` / `valid_to` | 生效/失效时间(超期不参与) |

**一人可分管多个部门**(同 `vp_user_id` 配多行);某部门未配置时回退到普通四层解析。

## 5. 利率矩阵 `ccr_rate_matrix`

决定**审批链、终审岗位、边界利率**。是「这笔利率申请走到哪一级」的核心配置。

### 5.1 关键字段

| 字段 | 含义 | 示例 |
|---|---|---|
| `business_big_type` | 业务大类 | `LOAN_PUBLIC` 对公 / `LOAN_PERSONAL` 个人经营 / `DEPOSIT` 存款 / `MARGIN` 保证金 |
| `new_or_existing` | 新增/存量 | `NEW` / `EXISTING` |
| `customer_type` | 客户类型(空=通配) | `SOE` 国企 / `NON_SOE` 非国企 / `PERSONAL` |
| `product_code` | 产品编码(空=通配) | `LOAN_A` 对公 / `LOAN_P` 个人经营 |
| `amount_tier` | 金额档(空=通配) | `GE_5000` ≥5000 万 / `LT_5000` <5000 万 |
| `term_tier` | 期限档(空=通配) | 贷款 `1Y/3Y/5Y`;存款 `3M/6M/1Y/2Y/3Y` |
| `guarantee_type` | 担保方式(空=通配) | `MORTGAGE`/`PLEDGE`/`GUARANTEE`/`CREDIT` |
| `start_node_code` | **终审岗位**(链截断点) | `BRANCH_MANAGER` / `DEPT_GENERAL_MANAGER` / `VICE_PRESIDENT` / `SIX_PEOPLE_GROUP` |
| `dept_code` | **部门归属**(分流到哪个业务部门) | `COMPANY_FINANCE` 公司金融 / `CREDIT_REVIEW` 授信评审 / `RETAIL` 零售 |
| `boundary_type` | 边界语义 | `RATE` 直接利率 / `SPREAD` 存量降幅 |
| `boundary_min_rate` | 边界利率(%) | 贷款=该岗位最低可批利率;存款=期限上限 |
| `boundary_bp` / `bp_sign` / `lpr_term` | LPR+BP 表达 | `boundary_bp=40`、`bp_sign=+`、`lpr_term=1Y` → LPR1Y+40BP |
| `priority` | 匹配优先级(低值优先,链式:1 支行 → 2 部门 → 3 分管 → 4 小组兜底) | 1~4 |

### 5.2 匹配与路由逻辑

1. 按 `customer_type / product_code / guarantee_type / amount_tier / term_tier` 逐维过滤(空=通配,不参与过滤);
2. 多个命中按 `priority` 取最低;同优先级多命中 = 配置错误(需修正);
3. 贷款:从优先级低到高,取**首个满足「申请利率 ≥ 边界」的节点**为终审岗位;全部不满足 → 小组兜底上会;
4. 存款/保证金:首行 `boundary_min_rate` 为上限,利率 ≤ 上限则支行终审,否则上会。

> **金额档取数**:有集团批复总额度按集团额度定档,无集团额度按申请金额,≥5000 万 = `GE_5000`。

### 5.3 部门归属透出

命中的矩阵行 `dept_code` 会**透出并冻结**到分项 `ccr_pricing_item.dept_code`,后续部门分流、部门总经理/分管行长解析都基于它。

| 矩阵 dept_code | 对应 `ccr_sys_dept.dept_code` | 部门 |
|---|---|---|
| `COMPANY_FINANCE` | `GSB` | 公司金融部 |
| `CREDIT_REVIEW` | `SXSB` | 授信评审部 |
| `RETAIL` | `LSB` | 零售金融部 |

## 6. 节点权限 `ccr_node_permission`

决定**某个岗位最多能直接批多少利率**——权限内直接通过,超权限整单上送(`ESCALATE`)。

| 列 | 说明 |
|---|---|
| `node_code` | 节点编码 |
| `role_code` | 岗位角色码 |
| `business_type` | `LOAN` / `DEPOSIT` |
| `boundary_min_rate` | **贷款**:本岗位最低可批利率(申请利率 ≥ 此值才在权限内) |
| `boundary_max_rate` | **存款**:本岗位最高可批利率(申请利率 ≤ 此值才在权限内) |
| `effective_from` / `effective_to` | 有效期 |

**判定逻辑**:
- 贷款:申请利率 ≥ `boundary_min_rate` → 权限内,本岗位直接通过;否则超权限,上送下一岗位;
- 存款:申请利率 ≤ `boundary_max_rate` → 权限内;
- 未配置该节点 → 视为权限内(放行)。

> 它与利率矩阵的分工:矩阵决定**审批链走到哪**,节点权限决定**走到某级时能不能直接批**。两者边界利率建议保持一致,避免「矩阵说支行终审、权限又说支行无权」的矛盾。

## 7. 部门分流口径

**部门分流 = 把不同业务的审批分到对应业务部门的处理人**,节点链本身不变。

| 业务场景 | 分流到部门 | dept_code |
|---|---|---|
| 对公**存量**(调息) | 公司金融部 | `GSB` |
| 对公**新增**(授信) | 授信评审部 | `SXSB` |
| 个人经营贷 | 零售金融部 | `LSB` |

实现路径:
1. 利率矩阵命中行的 `dept_code` 透出,提交时冻结到 `ccr_pricing_item.dept_code`;
2. 部门总经理节点指派配 `GSB:dept_gm` / `SXSB:dept_gm` / `LSB:dept_gm` 多行(第 3.3 节「含冒号」写法);
3. 审批时按分项的 `dept_code` 精确命中对应行,取该部门下 `dept_gm` 角色用户;
4. 分管行长节点同理,但优先走 `ccr_dept_vp` 映射(第 4 章)。

> 加新部门、调整部门归属,改矩阵行的 `dept_code` + 指派行即可,审批链代码不动。

## 8. 常见调整场景(照步骤改表)

| 场景 | 操作 | 涉及表 |
|---|---|---|
| **换部门总经理** | 给目标机构(`ccr_sys_dept.id` 对应 GSB/SXSB/LSB)下新增一个 `dept_gm` 角色启用用户,或停用旧用户 | `ccr_sys_user`(改 role_code/org_id/status) |
| **部门改名** | 只改 `ccr_sys_dept.dept_name` | `ccr_sys_dept` |
| **换支行行长** | 改 `BRANCH_MANAGER` 节点的 PERSON 指派(assignee_code=新工号),或给 `branch_manager` 角色加人 | `ccr_node_assignee` / `ccr_sys_user` |
| **加审批人** | 给对应角色加启用用户(`ROLE`/`GROUP` 层自动纳入) | `ccr_sys_user` |
| **改分管行长分管范围** | 调整 `ccr_dept_vp` 的 dept_code↔vp_user_id 映射 | `ccr_dept_vp` |
| **处理人临时出差** | 配置 `delegate_to` 代理 + 有效期 | `ccr_node_assignee` |
| **调某节点可批利率边界** | 改 `ccr_node_permission` 的 `boundary_min_rate`/`boundary_max_rate` | `ccr_node_permission` |
| **调某笔利率走到哪级终审** | 改 `ccr_rate_matrix` 对应行的 `start_node_code`/`priority`/`boundary_*` | `ccr_rate_matrix` |
| **调整金额档分界** | 改金额档定义(当前硬编码 5000 万阈值,需改代码) | —(代码) |
| **⚠ 新增/修改角色码** | 需改代码(角色码硬编码),并全局同步 | —(代码) |

**改表后的生效**:配置为**即时读取**(审批时动态解析),一般无需重启;涉及缓存字段时可在管理界面触发刷新。

## 附录 B 常见排查

| 现象 | 排查点 |
|---|---|
| 待办看不到某笔单 | 节点指派解析出的处理人里有没有当前账号;该账号 `status=ENABLE`;分项 `dept_code` 是否命中对应 `dept_code:role` |

| 分管行长不对 | 查 `ccr_dept_vp` 映射是否配了该部门;一人分管多部门需多行 |
