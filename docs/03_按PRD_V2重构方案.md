## 1. 核心差距评估(当前开发 vs PRD V2)

| 维度 | 当前开发(基于定稿版V1.0) | PRD V2 要求 | 差距 |
|---|---|---|---|

| 审批原子单位 | 合同/账户级定价分项 | **担保类型分项**(同一申请多担保类型各自独立) | ❌ 需重构 |
| 路由依据 | 通用规则表(手动) | **LPR±BP 参数化权限矩阵**(§7.2 表7.2.1-7.2.4:存量/新增、金额<5000万/≥、国企/非国企/个人、期限档) | ❌ 需重写 |

## 2. 重构计划(按优先级)

### 2.1 领域模型对齐(后端 + 数据库)
- **保留集团模型**(用户确认):定稿版 V1.0 的集团→成员→定价分项继续执行。
- **对齐逐担保类型粒度**:申请/定价分项支持"同申请多担保类型各自独立路由/校验/计票"(D5/D18a)。
- **状态机对齐 PRD V2 §7.6**:DRAFT→SUBMITTED→ROUTING→APPROVED_LEVEL→FINAL / VOTING→COMMITTEE_PASS→PRESIDENT_DECISION→FINAL / VETOED / RETURNED→DRAFT。

### 2.2 权限矩阵 LPR±BP 重写(§7.2)
- **LPR 参数**:一年期/五年期以上,人工维护(计划财务部),LPR 调整后阈值自动换算。
- **权限矩阵配置**:按表 7.2.1-7.2.4 建模——业务类型(存量/新增)、客户类型(对公国企/非国企/个人经营)、金额档(<5000万/≥5000万)、期限档(一/三/五年)、担保类型;每档位配置 终审岗位 + 利率边界(BP 或绝对值)。
- 路由:提交时按维度匹配 → 唯一终审岗位;低于边界→上会(小组表决)。

### 2.3 表决:按担保类型独立计票(D5)
- 同申请多担保类型各自投票、各自 ≥4 票通过;任一类型未过仅该类型退回。

### 2.4 贡献度双概念(D15/D21)
- 当前贡献度(数仓,勾稽校验)与拟达成贡献度(申请录入,承诺基线)并列展示。
- 达成跟踪:承诺按指标 code 客户级聚合 = 分母;数仓最近批次当前贡献度 = 分子,逐项对比,月报提醒。

### 2.5 前端按 design-system 优化
- 品牌蓝 #2563eb;组件 BEM。
- 页面:PC 工作台(工作台/新建申请/历史申请/承诺跟踪/消息)、申请(担保分项录入+贡献度双概念)、审批详情(stepper+按类型计票)、移动审批端。

## 3. 执行顺序

1. **权限矩阵 LPR±BP**(路由引擎重写,PRD §7.2 核心) → 2. **状态机对齐 PRD V2**(§7.6) → 3. **逐担保类型独立计票**(D5) → 4. **贡献度双概念对齐**(D15/D21) → 5. **前端 design-system 优化** → 6. 端到端验证。

> 集团模型保留(定稿版 V1.0);其余按 PRD V2。外部数据表结构(`dw_*`/`caps_*`)仍按 PRD §8 数据仓库契约保留。

## 4. 部门分流方案 A(§D16a)——需求与决策记录

> 需求原文(PRD D16a):「岗位部门归属:权限矩阵中"部门总经理/分管行领导"按业务类型归属部门——**对公存量 → 公司金融部**;对公新增授信 → 授信评审部;个人经营性贷款 → 零售金融部。审批沿归属自动路由对应部门岗位。」用户确认的落地口径与决策如下(2026-08-11)。

### 4.1 三口径部门分流(全档生效)

| 业务口径 | 归属部门 | 部门总经理 | 分管行领导 |
|---|---|---|---|
| 对公存量 | 公司金融部(GSB) | 该部门 dept_gm 角色用户 | 公司金融部分管行长 |
| 对公新增授信 | 授信评审部(SXSB) | 该部门 dept_gm 角色用户 | 授信评审部分管行长 |
| 个人经营性贷款 | 零售金融部(LSB) | 该部门 dept_gm 角色用户 | 零售金融部分管行长 |

> 注(2026-08-14 机构迁移):本方案中的字母码 `GSB/SXSB/LSB` 已废止,部门标识统一为真实机构 `org_code`——公司金融部 `3202233912` / 授信评审部 `3202233943` / 零售金融 `3202233991`;矩阵 `dept_code`、节点指派(`3202233912:dept_gm` 等)、`ccr_dept_vp` 全部按 org_code 对齐。

- **分的是节点内处理人,不是节点链**:链路 `BRANCH_MANAGER→DEPT_GENERAL_MANAGER→VICE_PRESIDENT→SIX_PEOPLE_GROUP` 不变;部门总经理/分管行长节点按分项 `dept_code` 解析处理人。
- **全档生效**:金额档(LT_5000/GE_5000)各档均配置 dept_code,5000 万以上存量/新增同样按部门分流。

### 4.2 配置化约束(用户重点关切)

- 机构/用户为样例数据,真实环境会调整机构号/部门名。审批流必须**配置驱动、动态可调**,不能因改样例数据而断。
- **部门标识用稳定编码,不靠部门名**:矩阵 `dept_code` 统一为机构部门编码(GSB/SXSB/LSB),经 `ccr_sys_dept.dept_code` 关联机构;部门改名只改 `dept_name`。
- **部门总经理不靠具体工号**:指派配置用「机构dept_code:角色码」语法,换总经理/加人只改机构角色配置。
- **分管行领导一人可分管多部门**:新增 `ccr_dept_vp` 映射表,纯配置调整分管范围(演示:公司+零售同一分管行长、授信另一分管行长)。
- **角色码是唯一代码硬编码项**:沿用标准角色码体系(branch_manager/dept_gm/vice_president/committee_member/president),不新增。

### 4.3 近期其他需求同步

- **流程轨迹增强**:审批轨迹从客户经理提交申请开始显示,含当前执行状态、到达当前节点时间、处理人姓名;客户经理待办/「我的申请动态」能看到申请走到哪、在哪卡着、何时提交到该节点。
- **我的申请工作台**:页签统一为「我的工作台」(内含审批内容);「我的申请」仅显示在途申请,终态走历史档案;行内提供「查看档案」入口(档案信息+流程轨迹)。
- **样例单演示**:单申请多分项审批(贷款与担保信息并入审批决定区,每分项含合同+借据+担保+利率输入框+按钮)。
