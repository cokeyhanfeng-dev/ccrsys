# 29 集团授信金额定档修复方案

> 状态：待评审（2026-08-28 用户拍板「先不动，仅出方案」）
> 关联：#400 集团申请金额定档口径确认

## 一、需求口径（用户定义）

> 「集团的申请是按照**每一个授信的授信总额**去走，而不是按分项的总和去走。」
> 「集团授信的那个，就是申请界面前面输入的、对新增授信来说叫做"总授信额度"的那个字段；对于存量的，就是当前授信协议选择授信协议的总额度。」

即集团申请与普通申请一致，按 **`credit_info_json.totalCredit`（申请界面「总授信额度」字段）** 定金额档：
- 新增授信 = 申请页手工录入的总授信额度
- 存量授信 = 申请页选择的授信协议总额度

## 二、现状确认（2026-08-28 复核）

### 2.2 问题结论

**集团客户当前定档 = 数仓集团综合授信批复总额度（`dw_group_credit_snapshot.approved_total_amount`），覆盖了申请界面「总授信额度」字段（totalCredit）。**

- `amount`（totalCredit）在两侧都已正确计算并传入，但被 `groupCreditTotal` 覆盖。
- 非集团客户 `groupCreditTotal=null`，走 `amount`（= totalCredit），**已符合**「按授信总额定档」；集团客户是唯一走数仓批复总额的场景。
- 秘书岗触发已按 `amount`（totalCredit），不受本问题影响。

## 三、修复方案

两方案最终效果一致：**集团也按 `credit_info_json.totalCredit` 定金额档**。

### 方案 B（推荐，改动最小）

把调用方 `amountBasis` 显式改为 `APPLY_AMOUNT`，让矩阵定档走 `amount`：

```java
// ApplicationSubmitServiceImpl.buildRouteInput L1428
input.setAmountBasis(MatrixRouteInput.AMOUNT_BASIS_APPLY_AMOUNT);
// ApprovalServiceImpl.recalcRoute L2224
input.setAmountBasis(MatrixRouteInput.AMOUNT_BASIS_APPLY_AMOUNT);
```

- 改动 2 处；`RateMatrixRouterImpl` 的 match/上会条件逻辑不动
- `groupCreditTotal` 字段与 `GROUP_TOTAL_CREDIT` 常量保留（兼容其他调用/后续扩展），仅集团定档不再走它
- 单测已有 `APPLY_AMOUNT` 路径覆盖（`RateMatrixRouterImplTest` L455「集团场景_显式APPLY_AMOUNT按申请金额定档」、`RuleEngineImplTest` L270），规则层无需改测试

### 方案 A（彻底，改动面大）

`RateMatrixRouterImpl` 两处定档（L252-255、L416-419）去掉 `groupCreditTotal` 优先，恒用 `input.getAmount()`：

```java
BigDecimal basis = input.getAmount() == null ? BigDecimal.ZERO : input.getAmount();
```

- 改动 2-3 处规则层逻辑 + 同步更新 `RateMatrixRouterImplTest` 既有「集团按批复总额」用例
- `groupCreditTotal` 定档用途废弃，字段保留
- 影响面更大，但语义更彻底（不存在两套口径并行）

> 注意：`RuleEngineImpl.match`（L166-176）用独立 `RuleInput.groupCreditTotal` 做集团授信额度规则匹配（`group_credit_min/max`），**不属于本次定档口径，不改**。

## 四、影响面

- **受影响**：集团客户（customerScope=GROUP）贷款申请的矩阵金额档匹配（LT_1000/GE_1000_LT_5000/GE_5000）与上会条件判定 → 金额档可能从批复总额档切到总授信额度档，影响终审岗位/链路。
- **不受影响**：非集团申请（已按 totalCredit）；存款（固定链不上矩阵金额档）；秘书岗触发（已按 amount）；`RuleEngineImpl` 集团授信规则（独立 DTO）。
- **历史存量**：已冻结 route_code/route_chain 的进行中申请不受影响（路由已冻结）；新提交/调价重算才走新口径。
