# 数仓数据需求清单（交付数仓团队）

> **用途**：客户贡献度与利率决策系统所需的数仓加工数据，共 **19 张契约表**。
> **消费方式**：数仓按本清单表结构加工后，**直接推送落库**到业务库 `ccr_rate`；本系统直接读表访问，对所有落地表**只读**（展示/勾稽/快照冻结）。
> **契约基准**：本文档 + `db/02_external_data.sql` 实际 DDL。内部设计细节见 `docs/09_数仓加工表清单.md`。
> **版本**：v1.0 / 2026-08-17

---

## 一、通用约定（所有表）

| 项 | 约定 |
|---|---|
| 字符集 | `utf8mb4` |
| 金额 | `DECIMAL(18,4)`，单位**万元** |
| 利率 | `DECIMAL(7,4)`，百分值（如 `3.8500` = 3.85%） |
| 敏感字段 | 证件号 / 存款账号**明文存储**（2026-08-17 明文化） |
| 批次标识 | `etl_md5` 主键 + `data_dt` 数据日期；业务读取**最新 `data_dt` 成功批次** |
| 数据时效 | 快照数据容忍默认 3 个自然日（`data-stale-days=3`），各表批次频率需满足 |
| 批次幂等 | 暂以 `etl_md5` 主键 + `data_dt` 批次标识（业务主键未建批次级唯一约束，已记录决策暂不加） |

### A06 当前贡献度 `dw_contribution_metric`

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| etl_md5 | BIGINT | PK | 自增 |
| data_dt | DATE | 是 | 数据日期 |
| cust_no | VARCHAR(32) | 是 | 客户号（`idx_cust`/`idx_cust_code`） |
| metric_code | VARCHAR(40) | 是 | 指标编码；**TOTAL=综合贡献总额行**，其余为明细 |
| metric_name | VARCHAR(64) | 是 | 指标名（TOTAL 行为综合贡献总额） |
| metric_value | DECIMAL(18,4) | 是 | 指标值（万元）；TOTAL 行为综合贡献总额 |
| value_type | VARCHAR(20) | 是 | AVG_BALANCE 业务余额 / INCOME 收入 / CONTRIBUTION_AMOUNT 折算；TOTAL 行为 CONTRIBUTION_AMOUNT |
| metric_scope | VARCHAR(15) | 是 | PUBLIC / PRIVATE_SELF / RELATED 关联人 / GROUP 集团 / GROUP_MEMBER 集团成员；单户 TOTAL 行为 PUBLIC，集团 TOTAL 行为 GROUP |
| stat_start | DATE | | 统计区间起（主客户与关联人须一致） |
| stat_end | DATE | | 统计区间止 |
| calc_version | VARCHAR(32) | 是 | 贡献度计算口径版本（默认 V1.0） |

> **加工要点（重点）**：
> - **系统侧指标编号以 `ccr_metric_definition` 指标字典为准**（后台「参数管理→指标字典」页 admin 配置化维护；数仓新增指标在字典登记即可，前端无需改代码）。
> - TOTAL 为**明细加总展示汇总**指标（系统侧仅作展示汇总，不自行折算 FTP/费率）；明细加总须与 TOTAL 勾稽一致。
> - **指标清单**：对公 9 项 `PUBLIC_DEPOSIT_AVG`、`PUBLIC_PROJECT_LOAN_AVG`、`PUBLIC_DISCOUNT_SPREAD`、`PUBLIC_OFF_BALANCE_INCOME`、`PUBLIC_EXCHANGE_SPREAD`、`PUBLIC_PAYROLL_CONTRIBUTION`、`PUBLIC_PAYROLL_AMOUNT`、`PUBLIC_WEALTH_INCOME`；对私 3 项 `PRIVATE_DEPOSIT_AVG/LOAN_AVG/WEALTH_INCOME`；派生 `PUBLIC_DEPOSIT_LOAN_RATIO`（RATIO，不参与勾稽）。
> - 关联人贡献度按**证件号**反查承载 `metric_scope='RELATED'`（无独立关系表）。
> - 集团 TOTAL 行 = 成员合计，防重复归集（`metric_scope='GROUP'`）。

## 四、关键加工口径（数仓需保证）

1. **A06 贡献度勾稽**：TOTAL 行由数仓权威折算提供，明细加总必须与 TOTAL 一致；主客户与关联人统计区间须一致；集团 TOTAL = 成员合计防重复归集。
2. **A10 机构达成**：`snapshot_ts` 为唯一落地时间戳列；达成率分子 = 数仓贡献度，分母 = 系统已通过申请承诺合计。
3. **B04 集团金额档判定**：系统按 `approved_total_amount` 判定集团金额档次（避免成员拆分规避权限层级），须为数仓权威批复总额。
4. **B07/B08 决议核验**：决议生成时比对申请利率与合同/借据执行利率，`execution_rate` 必须为最新合同执行利率。
5. **B07 存量贷款**：申请页存量贷款调息统一从贷款合同取（`borrower_customer_no` 匹配），`contract_balance`/`guarantee_type`/`execution_rate` 口径须完整。
6. **B09 存款账号**：明文反查，按 `deposit_account_no` 精确匹配。
7. **C21/C22 授信担保拆分明细（2026-08-25）**：按「授信 × 担保方式」拆好推送，`split_no` 唯一；抵押物/保证人字段对齐 A04/A05；`split_status='EFFECTIVE'` 才消费。

## 五、待数仓确认项

1. **批次频率与推送方式**：各表 T+1 批次与成功事件推送方式待数仓确认。
