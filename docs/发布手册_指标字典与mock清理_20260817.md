## 3. 数据库变更

### 3.1 运行库（已有数据的环境）

仅需执行一条幂等迁移（指标字典基线）：

```bash
docker exec -i ccr-mysql mysql -uroot -proot123 --default-character-set=utf8mb4 ccr_rate < db/25_metric_definition_seed.sql
```

- **幂等**：重复执行安全（`uk_metric_code` 冲突走 ON DUPLICATE KEY UPDATE，仅刷新名称/类型/范围/单位/版本）。
- **可验证**：`SELECT COUNT(*) FROM ccr_metric_definition WHERE status='ACTIVE';` 应为 **16**。
- 指标字典后续由 admin 在「参数管理 → 指标字典」界面维护（增改停用即生效），本文件仅初始化基线，**生产不重跑**。

### 3.2 运行库 mock 用户清理

本次代码已删 10 个 mock 账号种子；**运行库清理已于交付前完成并验证**（10 账号物理删除、user_post 无残留、4 个系统账号在位）。若在全新环境初始化，直接按种子文件建库即可；**不要在已有生产运行库重跑 `db/08_system.sql`**（含系统主数据，非幂等）。

## 4. 构建部署

```bash
cd G:/project/ccr
docker compose build --no-cache backend    # BuildKit 缓存坑：改 Java 必须 --no-cache
docker compose build frontend              # 前端新增 store/文件，需重新构建
docker compose up -d
```

- **前端** nginx 对 index.html 禁缓存、静态资源 hash 长缓存，刷新浏览器即可看到新 tab。
- 若先停后端验证「静态回退」（场景 O-4），恢复后前端会自动重连读字典，无需重启前端。
- 改种子/DDL 后如需重建库，仅限**测试环境**：`docker compose down -v && docker compose up -d --build`（**生产严禁 -v**，会丢数据卷）。
