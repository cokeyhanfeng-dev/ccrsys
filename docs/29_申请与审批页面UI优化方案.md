## 1. 现状主要问题（摘要，均有行号证据）

**利率申请页 loan.vue**
1. 集团区块三层卡片嵌套：客户信息卡 ⊃ 新增集团补录卡(:180) ⊃ 手工成员补录卡(:277)，补录行还有手绘内联边框(:281)
2. 成员表无标题、无操作列（:242-269）——首次进页面不知道这是什么表；手工补录的成员进表后无法删除
3. 只读字段（集团编号/评级）和可编辑字段外观无区分，混排在同一网格（:44-85）
4. 字段说明全塞 placeholder（"数仓带出，可修改"出现 10+ 次），聚焦即消失
5. 「成员 × 担保项」实为逐个手选（:581-589），集团 8 个成员就要手工加 8 次分项
6. 7 步向导信息密度极不均：Step 3 塞 270 行模板，Step 6 只剩一个 textarea（"提交预览"名不副实，预览全在弹窗里）
7. 窄屏基本不可用：4 列网格只在 1100px 降 2 列，无单列断点；步骤条 900px 下横滚

**审批详情页 detail.vue**
1. 单页瀑布 14+ 张卡顺序堆叠，审批人要滚过 10 张只读卡才能到「审批决定」(:618)，无锚点/tab/吸顶
2. 区块注释编号 0→4→5→6→6c→6b→7b→7c→8→9→… 不单调，历史叠加无组织
3. 超宽表格：分项表 12 列(:54)、关联人表 12 列(:268)，PC 必横滚
4. 担保信息表套表三层（:662-743）
5. 审批意见和一键操作在最底部(:790-804)，与分项操作(:758/:782)分离，分项多时来回滚
6. 几乎每个卡都有空态分支，整页可能连续多张空态卡
7. 同一"键值摘要"全站三套私造（`.detail-grid` / `.confirm-summary` / `.credit-overview`），loan 第一步 label 横排 vs 第三步起置上，两套风格并存

## 2. 优化设计

### 2.1 设计系统先补三件基础设施（所有页面受益）

| 候选类 | 解决什么 |
|---|---|
| `.desc-grid` / `.desc-item__label/__value` 描述列表 | 统一三套私造键值网格；**只读信息一律用描述列表呈现，不再用灰 input** |
| `.page-action-bar` 吸底操作条 | 表单页（存草稿/上下步）与审批页（意见+一键通过/否决）操作随手可及 |
| `.form-group-title` 表单分组标题 + `.form-hint` 字段说明 | 长表单分组（基本/开户/集团关系），说明文案从 placeholder 移到 hint，聚焦不消失 |

### 2.2 申请页（重点：集团客户）

1. **集团信息 → "集团档案"卡**：查询行（联想搜索 + 编号只读文本）→ 命中后展示只读档案（描述列表 + 数仓徽标 + 数据日期）→ "信息有误？手工修正"折叠入口。数仓未收录时同一张卡切换为补录模式，**字段分两组（基本信息 / 开户信息）**，三层嵌套卡拆除。
2. **成员管理 → "集团成员"卡**：工具条 = 标题 + "已选 N/M" + 说明文字 + 操作（＋手工补录 / 批量导入）；表格增加"来源"列（数仓/手工徽标）和"操作"列（**手工成员可删除**）；勾选语义写明"勾选结果作为利率申请步分项的成员选项"。
3. **手工补录成员 → 弹窗**：从页面第三层嵌套卡改为模态弹窗，字段同样分组（基本信息 / 集团关系），占位号规则用 hint 说明。
4. **分项生成 → 工具条加"按成员批量生成"**：一键按已勾选成员各生成一个空白分项，再逐个补担保方式等字段；分项卡头部显示"成员名 + 担保方式徽标"，一眼分清。
5. 步骤条 7 步合并为 6 步（材料附件并入"承诺与材料"）；Step 6 恢复真正的内联预览（概要+明细+路由），不只靠弹窗；`v-show` 改 `v-if`，不再全步骤 DOM 常驻。
6. label 全页统一置上；网格补 768px 单列断点。

### 2.3 审批详情页

1. **吸顶摘要条**：申请号 / 客户 / 金额 / 业务类型 / 当前节点 + **锚点导航**（申请内容 / 客户与集团 / 承诺与履约 / 流程轨迹 / 审批决定），任何位置一键跳到操作区。
2. **五段式组织**替代 14 张卡瀑布：申请内容 → 客户与集团 → 承诺与履约 → 流程轨迹 → 审批决定；低频只读资料（成员明细/他行融资/关联人等 9 项）默认折叠为一行轻提示，需要再展开。
3. **宽表收敛**：分项表 12 列 → 6 主列 + "明细 ▸"展开行；担保信息表套表三层改为一层表 + 明细抽屉。
4. **审批操作**：分项卡内保留逐项操作（利率对比条 + 同意/否决本项）；**审批意见 + 一键通过/否决/整单上送吸底固定**，消灭"分项操作在上面、意见和整单按钮滚到底"的来回滚动。
5. 承诺与历史履约合并为一段左右双栏（复用 contribution-grid），消除成员折叠面板与 ContributionPanel 的重复展示。
6. 空态整卡 → 一行 `.empty-line` 轻提示。

### 2.4 不改的东西

布局框架（app-shell/侧栏）、设计系统色板与组件词汇、路由与数据接口、提交确认弹窗 SubmitCheckDialog（本身形态健康）、后端任何逻辑。本次是纯前端信息架构与样式层优化。

## 4. 决策点（已拍板，2026-08-25）

| # | 问题 | 结论 |
|---|---|---|
| D1 | 步骤条保留分步向导（优化版）还是改单页锚点长表单？ | **保留分步**：7 步合并为 6 步（材料附件并入"承诺与材料"），步骤切换 v-show→v-if，允许跳步 |
| D2 | 审批页低频资料"默认折叠一行提示"的折叠范围 | 按实施版：授信信息/附件/他行融资/关联人/机构达成五卡默认折叠 |
| D3 | 集团多成员的分项组织方式 | **成员 Tab**（原型第三版）：每个已选成员一个页签，角标分项数、0 项黄标；页签内添加分项成员预设；"为每个成员生成一个分项"复制首个分项的担保方式/期限；卡顶额度勾稽条实时核对 |
| D4 | 移动端是否本期做 | 本期只补 768px 单列断点"可用"，移动审批另行立项 |
