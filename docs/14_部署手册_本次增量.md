- **面向对象**：部署人员

## 一、本次增量内容

1. **数据库**：`ccr_sys_user` 加 `pwd_change_flag` 列 + 存量账号密码统一重置为初始密码
2. **后端**：强密码校验、首次登录强制改密、主动改密接口、BFB4 草稿重复提交修复
3. **前端**：改密页 + 登录分流 + 顶栏「修改密码」入口

> ⚠️ 迁移执行后**所有存量账号密码变为统一初始密码，首次登录必须改密**。初始密码值另行向部署方提供，请提前通知用户。

---

## 二、执行顺序（重要：SQL 必须先于后端）

> 后端新代码登录会读取 `pwd_change_flag` 列，**列不存在会报错**，故先执行 SQL 再部署后端。

### 第 1 步：执行 SQL 迁移

用仓库 `db/23_password_change_flag.sql` 执行（文件含初始密码哈希，**仅内部向部署方提供，不要进公开仓库**）。

> 迁移脚本内容：① 为 `ccr_sys_user` 加 `pwd_change_flag` 列（幂等，可重复执行）；② 将未逻辑删除且未改密（`pwd_change_flag='1'`）的存量账号密码重置为统一初始密码。

执行（`ccr_rate` 为库名，按生产实际调整；脚本幂等，可重复执行）：

```bash
docker exec -i ccr-mysql mysql -uroot -proot123 --default-character-set=utf8mb4 ccr_rate \
  < 23_password_change_flag.sql
```

执行后核对：

```sql
SELECT username, pwd_change_flag FROM ccr_sys_user WHERE del_flag='0';
-- 期望:全部 pwd_change_flag = '1'
```

### 第 2 步：部署后端

```bash
cd <项目根目录>
docker compose build backend
docker compose up -d --no-deps backend
curl http://localhost:8080/health   # 期望 ok/UP
```

### 第 3 步：部署前端

**必须先 `npm run build` 再构建镜像**（Dockerfile 是 `COPY dist` 模式，跳过 build 会拿到旧页面）：

```bash
cd <项目根目录>/frontend
npm run build          # 生成 frontend/dist,需 Node 环境
cd ..
docker compose build frontend
docker compose up -d --no-deps frontend
```

## 四、注意事项

1. **seed 文件不重跑**：`db/08_system.sql`、`db/18_contract_operator.sql`、`db/03f_node_assignee.sql` 仅全新环境初始化用，本次**只执行 23 号**，不要重跑，否则覆盖线上数据。
2. **所有账号（含 admin）** 初始密码统一，首登强制改密（初始密码值另行内部提供）。
3. **前端镜像坑**：跳过 `npm run build` 时 Docker 显示 `COPY dist CACHED`，页面仍是旧的，务必先 build。
4. 23 号 SQL 涉真实数据，仅内部传递，不入公开仓库。
