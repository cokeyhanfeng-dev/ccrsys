# 承诺跟踪简化改造方案（v2 · 无定时任务版）

> 状态：设计稿，待评审。**本方案只出设计，不含任何代码改动。**
> v2 说明（2026-08-25）：按需求方意见二次简化——**完全取消定时任务**。当前完成度实时计算（数仓最新值 vs 承诺目标）；到期完成情况惰性归档（查询时结算写表）；机构达成率直接查归档数据。
> 业务口径（需求方拍板）：
> 1. 数仓每天推当前贡献度值；
> 2. 在跟踪中的：数仓值 ÷ 承诺值 = 完成比例，查询时实时算出（前端/查询层加工），多指标取算术平均；
> 3. 到期判定完成/未完成，把完成情况写入历史表：① 各指标当前的值 ② 申请时的目标 ③ 机构/客户/客户经理关联；
> 4. 机构达成率：直接依据已截止的历史完成情况统计展示；
> 5. 承诺目标类型只保留三种：目标余额(金额) / 笔数 / 比例，其余删除。

---

## 1. 总体思路

**一张跟踪表，三种读法，零定时任务。**

- **当前完成度 = 实时算**：查询时取数仓最新批次值 ÷ 承诺目标值，当场算出返回，不落库、不预计算。
- **历史完成情况 = 到期惰性归档**：任何读入口（跟踪列表/详情/机构达成率）先执行一次"到期结算"（sweep）：把 `end_date` 已过且未判定的记录取出，按**截止日口径**取数定案，写终态字段。无人查看则不写，但任何统计与展示永远先结算再出数，口径始终一致。
- **机构达成率 = 查终态行**：一条 SQL 聚合，统计前先 sweep 保证完整性。

`end_date`（申请时录入的承诺截止日期）是唯一时间基准，彻底消除旧实现"计划+1年 vs 承诺截止日期"的双口径问题。

## 2. 数据模型（新增 1 张表，旧表保留只读）

### `ccr_commitment_track`（承诺跟踪表：在途行 + 终态行即历史完成情况表）

| 字段 | 说明 |
|---|---|
| `id` / 公共审计列 / `version_no` | 沿用 BaseEntity 口径 |
| `track_no` | 跟踪编号（`TRK`+日期+序号） |
| `application_id` / `application_no` | 来源申请 |
| `customer_no` / `member_customer_no` | 客户号；集团成员承诺填成员号 |
| `org_id` / `manager_id` | **机构 / 客户经理关联**（申请人机构 + 申请人，机构达成率与考核维度） |
| `metric_code` / `metric_name` | 指标编码/名称 |
| `target_kind` | 目标类型：`BALANCE` 目标余额(金额) / `COUNT` 笔数 / `RATIO` 比例，**仅此三种**；单位随类型联动（万元/笔/%） |
| `target_value` / `unit` | **申请时需要达成的目标** / 单位 |
| `end_date` | 承诺截止日期（取 `ccr_application_commitment.end_date`） |
| `status` | `TRACKING` 跟踪中 / `FINISHED_MET` 已完成 / `FINISHED_UNMET` 未完成 |
| `final_actual` / `final_ratio` | **定案时的指标当前值 / 完成比例**（终态时写入，即"历史完成情况"） |
| `final_data_dt` / `finish_time` | 定案所用数仓批次日期 / 归档时间 |

唯一键：`uk_track(application_id, metric_code, member_customer_no)`（同申请同指标同成员只跟踪一次，天然幂等）。

要点：**在途行不存"当前值"**——当前值永远实时从数仓取，避免任何落库值与数仓漂移；终态行才固化 `final_actual` 等定案字段，满足"历史完成情况单独记录"的要求。

### 不需要的表

- 每日评估历史表（v1 的 `ccr_commitment_track_history`）：**取消**。没有定时任务就没有每日快照；历史完成情况 = 终态行的定案字段，曲线类展示不做。
- 旧体系 7 张表（plan/metric/member_alloc/tracking_evaluation/tracking_policy/_version/threshold）：停用保留只读，不迁移（见 §6 D3）。

## 3. 业务流转

### 3.1 开始跟踪（业务事件触发，非定时任务）

终审通过（分项 FINAL）时，经现有 Outbox `COMMITMENT_CREATE` 链路（保留触发点，只换消费者实现）：把该申请 `ccr_application_commitment` 每条承诺行转成一条 `TRACKING` 记录；否决不生成；重复触发由 `uk_track` 幂等。`OTHER`（其它类手工承诺）不生成跟踪记录，维持 `track_desc` 手工留痕。

### 3.2 当前完成度（查询时实时计算）

跟踪列表/详情接口对 `TRACKING` 行逐条：取 `dw_contribution_metric` 该客户（成员承诺取成员号）+ 该指标**最新批次**值 → `ratio = actual ÷ target_value`，连同 `data_dt`（数据日期，供页面提示数据新旧）一起返回。前端只负责展示与求平均：
- 申请级/客户级完成比例 = 各指标 ratio 算术平均（单项超 100% 按 100% 计再平均，见 §6 D2；展示仍显示真实比例）；
- 数仓暂无该指标批次 → 返回"暂无数据"，不计入平均。

### 3.3 到期结算（惰性归档，本方案唯一的"加工"）

所有读入口（列表/详情/机构达成率）共用一个结算方法 `settleExpired()`，读前先执行（同事务）：

1. 捞出 `status='TRACKING' AND end_date < today` 的行（可加 `LIMIT` 分批）；
2. 逐行取数：该客户+指标、**`data_dt ≤ end_date` 的最近批次**值——**必须用截止日口径取数，不能用结算当天的最新批次**，否则到期后数仓新推送的值会篡改判定结果（本方案关键正确性约束）；
3. 计算 `final_ratio`（≥1 完成），写 `status` / `final_actual` / `final_ratio` / `final_data_dt` / `finish_time`；条件更新（`WHERE status='TRACKING'`）保证并发与重入幂等；
4. 截止日前数仓无任何批次的行：按未完成判定，`final_actual` 记 NULL、`final_data_dt` 记 NULL，备注"数仓无数据"。

由此，"到时间节点把任务写进表"在没有任何定时任务的前提下成立：第一次有人看，它就归档；机构达成率统计前也先结算，统计永远完整。

### 3.4 机构达成率

直接聚合终态行（执行前先 `settleExpired()`）：

```sql
SELECT org_id,
       COUNT(*)                                AS finished_total,
       SUM(status = 'FINISHED_MET')            AS met_count,
       SUM(status = 'FINISHED_MET') / COUNT(*) AS met_rate,      -- 完成率(按笔数)
       AVG(LEAST(final_ratio, 1))              AS avg_ratio      -- 平均完成比例
FROM ccr_commitment_track
WHERE status IN ('FINISHED_MET','FINISHED_UNMET')
  AND end_date BETWEEN ? AND ?                -- 统计区间可选
GROUP BY org_id;
```

接口沿用 `GET /ccr/commitments/org-achievement`，换内部实现，前端无感。客户经理维度同理按 `manager_id` 聚合。

## 4. 停用与删除清单

| 对象 | 处置 |
|---|---|
| 旧体系 7 张表（plan/metric/member_alloc/evaluation/policy/policy_version/threshold） | 停用保留只读，不迁移 |
| 旧 4 个定时任务、跟踪策略配置页、预警灯色/风险等级、策略试算 | 全部删除/下线 |
| 每日评估 job、每日历史快照表 | **不建**（v2 无定时任务） |
| 到期未完成主动通知 | 默认**不做**（无定时任务就没有主动推送时机；可在结算时顺带生成一条站内通知记录，见 §6 D4） |
| 承诺录入的目标类型三分支（INCREMENT/TARGET_BALANCE/CUMULATIVE） | 收敛为 BALANCE/COUNT/RATIO 三种；存量映射：TARGET_BALANCE→BALANCE，INCREMENT/CUMULATIVE 旧行只读展示；前端录入下拉同步收敛 |
| 承诺录入（`ccr_application_commitment`、end_date 必填校验）、Outbox 触发链路、前端跟踪页框架 | 保留不动 |

前端跟踪页：列表（客户/指标/目标值/当前值(实时)/完成比例(实时)/截止日期/状态）+ 详情（承诺要素 + 定案信息）。无策略、无灯色、无曲线。

## 7. 与 v1 的差异对照

| 维度 | v1 | v2（本版） |
|---|---|---|
| 定时任务 | 1 个每日 job | **0 个** |
| 当前完成度 | job 每日落库 latest_actual/ratio | 查询时实时算，不落库 |
| 历史表 | 每日快照 history 表 | 取消；终态行定案字段即历史 |
| 到期判定触发 | job 扫描 | 读前惰性结算（任何入口先结算再出数） |
| 通知 | 到期未完成每日扫发 | 默认不做（可选惰性生成） |
| 取数正确性 | job 到期当天取最新 | 明确约束：归档按 `data_dt ≤ end_date` 最近批次定案 |
