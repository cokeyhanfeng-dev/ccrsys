## 四、SQL 执行（幂等，推荐直接用汇总文件）

两份脚本均幂等（`information_schema` 动态判断，列不存在才 ALTER / 先删键后删列），**重复执行无害**。按文件名升序整跑即可：

```bash
# 方式一（推荐）:汇总文件一次跑完
docker cp release/ccr_incr_20260903.sql ccr-prod-mysql:/tmp/ccr_incr_20260903.sql
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 ccr_rate' < /tmp/ccr_incr_20260903.sql

# 方式二:分份执行
for f in db/incr/20260902_001_remove_dept_code_legacy.sql db/incr/20260902_002_group_ucr_code.sql; do
  docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 ccr_rate' < "$f"
done
```

**执行后复验**：重跑 §三 的自查 SQL——`dept_code列=0`、`group_ucr_code列=1` 即达标。

> **集团 ucr_code 数仓侧提示**：`20260902_002` 加列后需数仓按新结构推送集团登记证号才有值；后端 `SELECT *` 已自动带出，数仓未推送前申请页集团 USCC 为空属正常（等数仓回推）。

> 两份脚本均无规则/矩阵/缓存类配置变更，**无需清理 Redis key**；SQL 变更对后端即时生效。

> ⚠️ **测试数据不入生产**：`db/incr/20260903_001_credit_split_agreement_linked.sql`（CUST001 协议切分演示）与 `db/incr/20260903_002_cust009_blend_demo.sql`（CUST009 综合利率演示）为**测试环境演示数据**，仅测试库执行，生产**勿跑**。
