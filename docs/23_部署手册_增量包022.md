> **适用范围**:已上线生产环境(v1.2 基线 `publish_full.sql` 后,已执行过部分增量),向最新增量包 `incr_20260821_022` 升级。
> **本手册覆盖**:021(贡献度口径修正,含 SQL)+ 022(开户机构下拉,纯代码),以及可能漏掉的 020(含 2 个 SQL)、019(角色删除修复,纯代码)。

在**生产 MySQL**执行以下查询判断缺哪些 SQL(避免漏执行):

```sql
-- 判断是否已到 021(有无 cert_type 列):
SHOW COLUMNS FROM ccr_application_related_person LIKE 'cert_type';
-- 有 → 021 SQL 已执行;无 → 需执行 20260821_003

```

## 四、后端 jar / 前端 dist 替换

### 1. 上传增量包

将 `release/incr_20260821_022/` 拷到生产机,得到 `backend/ccr-admin.jar` + `frontend/dist/`。

### 2. 后端 jar(替换 + 重启)

```bash
docker cp ccr-admin.jar <后端容器名>:/app/app.jar
docker restart <后端容器名>
```

### 3. 前端 dist(替换 + 重载)

```bash
# 先清旧 assets/index.html,避免旧 hash 文件堆积
docker exec <前端容器名> rm -rf /usr/share/nginx/html/assets /usr/share/nginx/html/index.html
# 用新 dist 覆盖
docker cp dist/. <前端容器名>:/usr/share/nginx/html/
# 重载 nginx(不中断连接)
docker exec <前端容器名> nginx -s reload
```

> 若生产用 docker compose 管理,也可用 `docker compose up -d --build backend/frontend` 整容器重建;推荐上述 `docker cp + restart/reload` 方式,不改变既有容器编排。

## 七、常见问题

1. **角色删除「点了没反应」** → 019 修复未部署,替换最新 jar 即解决(纯后端改动)。
2. **客户性质显示横杆** → 数仓主数据表(`caps_corp_cust_basic_info`/`caps_indv_cust_basic_info`)为空导致查不到客户,**非代码问题**;灌入数仓模拟数据后恢复。
3. **开户机构下拉为空** → 确认用客户经理或 admin 登录(接口对 `customer_manager/admin` 开放);未登录时接口返回 401 属正常。
