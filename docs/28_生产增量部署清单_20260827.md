## 四、SQL 执行（幂等，按需）

```bash
# 方式一:仅补前置种子(覆盖 GM 冒号/VP 账号/ccr_dept_vp/删 BM,幂等)
docker cp db/incr/20260827_001_deploy_prereq_seeds.sql ccr-prod-mysql:/tmp/20260827_001.sql
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ccr_rate' < /tmp/20260827_001.sql

# 方式二:若生产未执行 8-26 增量 002(report_date),补执行(幂等)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ccr_rate' < /tmp/20260826_002_credit_summary_report_date.sql

# 方式三:重置 message_key 溢出遗留的 FAILED Outbox 事件为 PENDING(幂等,仅 NOTIFY 类)
# 新 jar 部署后消费者会重新消费:scopedMessageKey 兜底生成的键 ≤64,不再 Data truncation
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" ccr_rate' -e "
UPDATE ccr_outbox_event
SET status = 'PENDING', retry_count = 0, update_time = NOW()
WHERE status = 'FAILED' AND event_type = 'NOTIFY';
"
```

**执行后复验**（跑 §三 的前置检查 SQL，六项计数达标即可）：
- `BM行=0`（9 行 BRANCH_MANAGER 终审行已删,支行行长仅必经过手）
- `GM冒号=3`（3202233912/3943/3991:dept_gm 冒号语法）
- `VP账号=3`（02300744/01500064/02300483 可登录,密码 `Yxnsh@1a3s`）
- `dept_vp=3`（三部门→VP 映射）
- `report_date=1`（若 8-26 已执行则为 1）
- `outbox_failed=0`（重置后消费者消费成功置 SUCCESS；若仍残留 FAILED 且重试耗尽，查消费者日志确认兜底键生效）

> 以上配置**均幂等**，重复执行无害；执行后可立即生效（`ccr_node_assignee`/`ccr_dept_vp` 均无缓存，后端无需重启）。FAILED 事件重置属生产排障动作，仅重置 NOTIFY 类、不动其它事件类型。

> **第 9 项可选扩列双保险（不执行也可，代码兜底已足够）**：`message_key` 列扩到 `varchar(128)`（幂等，仅变更列宽、不影响现有数据与索引唯一性）：
> ```sql
> ALTER TABLE ccr_notification_log MODIFY COLUMN message_key VARCHAR(128) NOT NULL COMMENT '消息幂等键';
> ```
> 已确认最长拼接 72 < 128，扩列后即使旧 jar 也不触发 Data truncation。
