# 移动审批实现与联调（2026-09-09）

## 范围与部署

沿用已确认的 `local-demos/mobile-approval` 视觉稿，正式代码位于 `frontend/mobile`。移动端是独立 Vue 入口，复用项目依赖和公共展示字典，构建到 `frontend/dist-mobile`。原型继续保留在 gitignore 目录；正式代码参与版本管理。

前端可部署在信贷看板服务器的独立 Nginx 站点；后台保留 CCR 生产区部署。网络链路为有度 WebView → 移动 Nginx → CCR `/mobile/**`，业务调用不经过 Magic API 或若依。与电脑端共用数据库、状态机、快照、规则版本及审批服务。`frontend/mobile/nginx.conf` 提供独立站点示例，内部地址由部署方替换，不包含生产连接信息。正式使用应在行内 HTTPS 入口后部署。

移动 Nginx 仅允许 `/mobile/api/mobile/**` 直达后端 `/mobile/**`，其余 `/mobile/api/**` 返回 404。仓库现有测试 Nginx 兼容独立入口 `/mobile/`。网络申请至少覆盖：手机到移动站点、移动 Nginx 到 CCR 后端、CCR 后端到有度验票服务。后端监听端口仍为容器内 8080；生产映射端口以部署文件为准。

## 有度免密登录

参考 digitalDashboard 的 `h5-workbench/src/main.js`、`public/youdu/youdu_sdk-1.0.js` 和 `/report/ydLogin` 协议：

1. 安卓调用 `window.youdu.getYdToken()`；iOS 通过 WebViewJavascriptBridge 调用 `getYdToken`，接收 `onGetYdToken`。
2. WebView 将 `{token}` POST 到同源 `/mobile/api/mobile/login`。不接受客户端自报账号、角色，不提供密码表单或演示账号登录入口。
3. CCR 向部署配置的固定有度验票 URL 发送 GET；拒绝重定向，设置连接/读取超时、限制响应大小，校验 `status.code` 及非空 `userInfo.account`。
4. 仅用验票响应的 `userInfo.account` 匹配 `ccr_sys_user.username`。检查账号启用和本地主角色准入，再签发独立移动 Sa-Token。临时有度凭证不写日志、不持久化到浏览器；身份凭证仅在 sessionStorage 保存 CCR 移动 token，另保存非敏感的登录来源标记。
5. 会话恢复通过 `/mobile/session` 再次校验账号及角色。电脑端会话不可调用移动接口，移动会话不可调用电脑端业务接口；服务端 TokenSession 保存渠道，不信任请求参数。既有电脑端 `/auth/login` 密码流程保持兼容。

准入主角色：`branch_manager/dept_gm/vice_president/secretary/committee_member/president`。秘书/委员兼岗沿用已有节点指派。客户经理、管理员、审计和合同操作岗不具有移动准入；客户经理即使被配置兼岗也不获得移动入口权限。对象与节点授权继续执行现有领域服务。

环境变量：

| 变量 | 含义 |
|---|---|
| `CCR_MOBILE_YOUDU_ENABLED` | 默认 false；接入真实验票服务后开启，无密码或账号回退 |
| `CCR_MOBILE_YOUDU_VERIFY_URL` | 完整固定 URL 模板，必须恰好包含一个 `{token}`；将 digitalDashboard 对应 `single.youdu` 的地址前缀转换为该模板，由部署环境提供 |
| `CCR_MOBILE_YOUDU_SUCCESS_CODE` | 验票响应 `status.code` 的成功值，默认 0；上线前必须核对实际服务响应，参考代码未显式验证该值 |
| `CCR_MOBILE_DEV_UPSTREAM` | 本地 Vite 代理后端地址，默认 `http://127.0.0.1:18080` |

`docker-compose.yml` 和 `compose.test.yml` 均透传三项有度配置。配置不齐或验票失败返回明确错误，不创建会话。桌面浏览器提示从有度打开；桥接等待最多 12 秒。

## 接口与业务约束

以下路径均相对后端 `/mobile`，返回统一 `R`（附件成功返回文件流）。除登录外要求有效移动会话。

| 方法 / 路径 | 能力与约束 |
|---|---|
| POST `/login` | 有度临时 token 换取 CCR 会话 |
| GET `/session`，POST `/logout` | 会话复核、退出 |
| GET `/tasks` | 本人普通审批、委员表决、行长决策待办；沿用现有授权查询 |
| GET `/done?page=1&size=20` | 本人普通审批轨迹、本人匿名票哈希、本人行长决策按申请去重；最大页长 100 |
| GET `/messages` | 当前登录人作为接收人的最近 200 条通知；不接收接收人参数，只返回内容/时间等展示字段 |
| GET `/applications/{id}` | 原审批详情的移动适配；保留对象权限，普通审批人/委员不返回他人票数、表决结果和行长意见 |
| POST `/approve`，`/reject` | `applicationId/nodeCode/versionNo/comment/rateAdjustments`；必传幂等键（最长 40 字符，为后端分项派生键预留空间） |
| POST `/vote-rounds/{roundId}/ballots` | `applicationId/choice/comment`，整单本人票；必传幂等键 |
| POST `/decisions` | `applicationId/decision/opinion`；复用行长服务的事务、状态检查和数据库唯一约束 |
| GET `/vote-rounds/{roundId}/opinions` | 复用原有行长权限与对象授权，返回匿名意见 |
| GET `/applications/{id}/attachments/{fileId}` | 先检查申请访问权限和附件归属，再读取数据库内容；no-store/nosniff |

移动同意/否决均二次确认，否决必填原因。贷款普通审批可逐项调价，秘书/表决/行长不提供调价控件；存款沿用现有审批不调价规则。每步 1 BP = 0.01 个百分点，前后端均校验相对原利率的整数 BP 差，保留原始小数精度。规则下限与流程去向全部由原服务执行，移除原型中 2.60% 等模拟判断。

提交等待时禁止重复点击。网络超时不当作成功，保留原请求体与原幂等键供人工重试，或返回待办重新核对。原服务重复请求可能返回“已处理”，此时重新加载待办判断结果。审批/调价轨迹的 `operation_channel` 从服务端会话写 `MOBILE`，电脑端仍记 `PC`；没有修改数据库结构。

## 附件

文件读取沿用 `ccr_application_attachment.content`，不需要手机连存储桶或数据库。下载携带 CCR 认证头，读取后创建临时 Blob URL。图片/PDF 根据文件签名决定预览类型，HTML/SVG 等不内嵌执行；其他格式提供下载。关闭预览时撤销 Blob URL 并中断在途请求。移动端预览大小上限 20 MiB（既有手工上传上限 10 MiB）；大文件提示使用电脑端。

PDF 使用客户端原生阅读能力，若 WebView 不支持内嵌 PDF，可下载后打开。Android/iOS 有度的 Blob 下载、PDF 阅读器和网络表现需要真机验收，此项不能由桌面构建结果替代。

## OA 免密认证补充（2026-09-09）

移动端同时支持 OA 与有度。OA 接入参考当前若依 `SysLoginController./oa/login` → `SysLoginService.loginByTicket/getUserByTicket`：后端向固定 OA 验票地址发起 GET，携带 `X-App-Id`、`apikey`、随机 `X-Sequence-No` 和 `yyyyMMddHHmmss` 格式 `X-Timestamp`；成功响应为纯文本账号。

OA 工作台将应用地址配置为移动入口 `/mobile/?ticket=<临时票据>`；兼容 `oaToken` 参数和 `#/callback?ticket=...` 形式。前端精确解析参数，拒绝空票、重复票据参数和两个别名同时出现。URL 中的票据在业务请求前用 replaceState 删除，随后 POST `/mobile/api/mobile/oa/login`，请求体为 `{ticket}`。不接收账号或任意验票 URL。新 OA 回调优先于浏览器中已有会话，旧移动 token 先清除，防止显示上一个账号的数据。

新增后端接口 `POST /mobile/oa/login`：登录白名单开放，DTO 校验票据后调用 OA 服务，验票取得账号后复用有度的本地主角色准入、停用检查和独立移动会话。客户经理同样被拒绝，电脑端密码登录入口保持兼容。

| 变量 | 用途 |
|---|---|
| `CCR_MOBILE_OA_ENABLED` | 默认 false；完成接入条件确认后启用 |
| `CCR_MOBILE_OA_VERIFY_URL` | 固定完整验票 URL 模板，恰好包含一个 `{ticket}`；对应参考代码的 `single.oa`，如需绑定回调 service/url，由服务端配置固定值 |
| `CCR_MOBILE_OA_APP_ID` | OA 验票请求 `X-App-Id`；对应参考代码 `proxy.appId` |
| `CCR_MOBILE_OA_API_KEY` | OA 验票请求 `apikey`；对应参考代码 `proxy.apiKey`，仅部署侧注入 |

两套 Compose 均透传上述配置，有度参数独立保留。OA 与电脑端统一认证的凭证分别配置，避免混用不同服务的应用标识。

验票严格要求 HTTP 200、非空且符合账号格式的纯文本响应；HTTP 401/403、重定向、HTML/JSON 错误对象、超时、过大响应均拒绝。连接超时默认 3 秒、读取超时 10 秒；响应最大 1024 字节。请求和异常不打印票据、apikey 或原始响应。Nginx 的移动访问日志不包含查询串/Referer，入口设置 no-referrer，避免携票 URL 被附带到资源请求；前置负载均衡/OA 侧日志需执行同等脱敏规则。

OA 失败不会自动切换到有度，也不会自动重试同一票据；提示从 OA 重新打开。用户可主动点击“使用有度登录”。票据有效期、应用归属和一次性消费必须由权威 OA 验票服务保证；启用前需核实实际接口的成功/失败响应以及这些约束。当前实现不缓存验票成功结果。此接入为“OA 已登录后携票进入”，直接访问普通浏览器时不会自动跳转未知的 OA 登录地址。

新增回归：`OaIdentityServiceTest` 验证请求头/票据编码/过期和异常响应；`MobileLoginTest` 验证 OA 使用验证后的账号建会话、客户经理拒绝且不回退有度；`oa.test.mjs` 验证 URL 清理、hash 回调、别名冲突与伪造 name 参数。
