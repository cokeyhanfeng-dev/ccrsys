# 重启/恢复指南

> 电脑重启或退出后，按本指南恢复环境与 Kimi Code 会话。

## 1. 恢复 Kimi Code 会话

打开终端（Git Bash 或 CMD），执行：

```bash
kimi -r session_3d971bfa-4306-42a3-8f0e-faabd48d8184
```

会话上下文完整保留，可继续之前的工作。

## 2. 重启系统（Docker 全栈）

1. 先启动 **Docker Desktop**（等其就绪）
2. 执行：

```bash
cd G:/project/ccr
docker compose up -d
```

3. 等约 1 分钟后访问：http://localhost:3000

**注意：**
- 不需要 `--build`（镜像已构建好；只有改了代码才需要 `up -d --build`）
- **绝不要加 `-v`**（`docker compose down -v` 会删除 MySQL 数据卷，全部业务数据丢失）
- 数据保存在 Docker 数据卷 `ccr_mysql-data` 中，重启不丢

## 3. 验证是否恢复

```bash
curl http://localhost:8080/health      # 后端,返回 status UP 即正常
```

前端 http://localhost:3000 能打开、能登录（zhangsan / 123456）即恢复完成。

## 4. 常见问题

| 现象 | 处理 |
|---|---|
| 页面 502 / 网络异常 | 后端还在启动，等 30-60 秒刷新；nginx 已配自动重解析，无需重启前端 |
| 端口被占用 | MySQL 用 13306（宿主 3306 被本机 MySQL 占用属正常）；8080/3000 被占用时 `docker ps` 找旧容器 `docker rm -f` |
| 提示数据过期阻断提交 | mock 数据日期过期,重跑:`docker exec -i ccr-mysql mysql -uroot -proot123 ccr_rate < db/15_test_data.sql` |
| 推送 GitHub 失败 | 本仓库已配局部代理 127.0.0.1:7890,确认代理软件已启动 |
