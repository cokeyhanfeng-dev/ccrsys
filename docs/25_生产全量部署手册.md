# 生产全量部署手册（容器化，2026-08-26）

> **适用范围**：生产环境 **大版本升级 / 全量重新部署**（清库重建）。采用容器化形态：MySQL 8.0 + Redis 7 + Spring Boot 3 后端 + Nginx 托管 Vue3 前端。
> **取代**：`docs/24_全量部署手册.md`（该文档基于 `publish_full.sql` + 10 个增量 + 单 jar 覆盖，已过时——未含 11-18 增量、无 prod profile、无 HTTPS、无生产编排文件）。
> **本手册与旧版的核心差异**：
> 1. 全量 SQL 收敛为**单个 `db/prod_full.sql`**（建库 + 全部表 + 必需初始化配置，已剔除全部测试/演示/模拟数据），不再手工跑 10 个增量。
> 2. 生产以 **`SPRING_PROFILES_ACTIVE=prod`** 启动，真实连接参数放在部署侧 `config/application-prod.yml`（挂载覆盖，不入库/不入镜像）。
> 3. 提供**独立生产编排** `docker-compose.prod.yml` + `.env` 模板；MySQL/Redis **不映射宿主端口**（仅内网）。
> 4. 前端可选 HTTPS（强烈建议，规避 http 非 secure context 下 `crypto.randomUUID` 抛错）。

- **时间基点**：SQL 覆盖 2026-08-26 最新状态（含 3 位分管行长账号、`pwd_change_flag` 首登强制改密、指标字典、流程引擎等全部增量）。

## 二、部署架构与拓扑

| 组件 | 镜像 | 容器名 | 宿主端口 | 说明 |
| --- | --- | --- | --- | --- |
| MySQL | `mysql:8.0` | `ccr-prod-mysql` | **不映射** | 仅 compose 内网访问；utf8mb4；数据卷 `mysql-data` |
| Redis | `redis:7-alpine` | `ccr-prod-redis` | **不映射** | 需 `--requirepass` 强密码；`--appendonly yes` 持久化 |
| 后端 | `ccr-backend:20260826` | `ccr-prod-backend` | `8080:8080` | Spring Boot 3，`SPRING_PROFILES_ACTIVE=prod` |
| 前端 | `ccr-frontend:20260826` | `ccr-prod-frontend` | `80:80`、`443:443` | Nginx 托管 dist + `/api` 反代后端 |

- **网络**：默认 compose 内网（project `ccr-prod`），`mysql`/`redis` 服务名可被 backend 直接访问。
- **时区**：MySQL/后端/Redis 均 `TZ=Asia/Shanghai`；JDBC `serverTimezone=Asia/Shanghai`；Jackson 时区 `Asia/Shanghai`（jar 内已配）。
- **服务间依赖**：backend `depends_on` mysql/redis **健康检查通过**后再启动；frontend 依赖 backend 启动。

## 九、Docker 编排（生产独立）

**新建 `docker-compose.prod.yml`**（与 dev `docker-compose.yml` 完全隔离；MySQL/Redis 不映射宿主端口；**不挂 `./db` initdb**）：

```yaml
# 生产环境编排(独立 project ccr-prod;与 dev docker-compose.yml 无关联)
name: ccr-prod
services:
  mysql:
    image: mysql:8.0
    container_name: ccr-prod-mysql
    restart: unless-stopped
    environment:
      MYSQL_ROOT_PASSWORD: ${MYSQL_ROOT_PASSWORD}
      MYSQL_DATABASE: ccr_rate
      TZ: Asia/Shanghai
      LANG: C.UTF-8
      LC_ALL: C.UTF-8
    command:
      - --character-set-server=utf8mb4
      - --collation-server=utf8mb4_general_ci
    # 生产不映射宿主端口:仅 compose 内网访问
    volumes:
      - mysql-data:/var/lib/mysql
      # 注意:生产禁止挂 ./db(initdb 会执行测试段 10/15/17/22);初始化手动执行 §十
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost", "-uroot", "-p${MYSQL_ROOT_PASSWORD}"]
      interval: 5s
      timeout: 5s
      retries: 30

  redis:
    image: redis:7-alpine
    container_name: ccr-prod-redis
    restart: unless-stopped
    command: ["redis-server", "--appendonly", "yes", "--requirepass", "${REDIS_PASSWORD}"]
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 5s
      timeout: 5s
      retries: 30

  backend:
    image: ccr-backend:20260826
    container_name: ccr-prod-backend
    restart: unless-stopped
    depends_on:
      mysql:
        condition: service_healthy
      redis:
        condition: service_healthy
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATA_REDIS_HOST: redis
      SPRING_DATA_REDIS_PASSWORD: ${REDIS_PASSWORD}
      TZ: Asia/Shanghai
    volumes:
      - ./config:/app/config
      - ./logs:/app/logs
    ports:
      - "8080:8080"

  frontend:
    image: ccr-frontend:20260826
    container_name: ccr-prod-frontend
    restart: unless-stopped
    depends_on:
      - backend
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./certs:/etc/nginx/certs:ro            # HTTPS 证书(部署侧提供;纯 HTTP 可去掉)
      - ./frontend/nginx-prod.conf:/etc/nginx/conf.d/default.conf:ro   # 生产 nginx 配置(§十一)

volumes:
  mysql-data:
```

**新建 `.env`**（生产机创建，**严禁入库**）：

## 十、数据库初始化

> ⚠️ **禁止** `./db` 挂载 initdb——`docker-entrypoint-initdb.d` 会按字母序执行 01→26 全部脚本，**包含测试段（10/15/17/22）**。生产必须手动执行下列步骤。

```bash
cd <部署目录>   # 含 docker-compose.prod.yml 与 .env

# 1. 起 MySQL / Redis(仅内网,不暴露宿主端口)
docker compose -f docker-compose.prod.yml up -d mysql redis
# 等待 healthy:docker compose -f docker-compose.prod.yml ps

# 2. 清空旧库(全量重建不可逆,务必先完成 §三 C1 备份)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "DROP DATABASE IF EXISTS ccr_rate; CREATE DATABASE ccr_rate CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"'

# 3. 灌入生产全量 SQL(宿主机已放置 prod_full.sql)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 ccr_rate' < db/prod_full.sql

# 4. 创建应用账号(§六 使用;如用 root 跳过)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' <<'SQL'
CREATE USER IF NOT EXISTS 'ccr_prod'@'%' IDENTIFIED BY '<APP_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON ccr_rate.* TO 'ccr_prod'@'%';
FLUSH PRIVILEGES;
SQL

# 5. 自检(执行 §五.3 断言;核心几条)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' -N -e "
SELECT CONCAT('tables=', COUNT(*)) FROM information_schema.TABLES WHERE TABLE_SCHEMA='ccr_rate';
SELECT CONCAT('users=', COUNT(*)) FROM ccr_rate.ccr_sys_user;
SELECT CONCAT('rate_limit=', COUNT(*)) FROM ccr_rate.ccr_product_rate_limit;
SELECT CONCAT('rule_set=', COUNT(*)) FROM ccr_rate.ccr_rate_rule_set;
"
# 期望:tables=102、users=79、rate_limit=2、rule_set=0

# 6. 清 Redis 旧缓存(重建后无残留 key;保险执行)
docker exec ccr-prod-redis redis-cli -a "$(grep '^REDIS_PASSWORD=' .env | cut -d= -f2-)" FLUSHDB
```

> `ccr_rate.` 前缀 + `information_schema` 双重写法仅为可读性；实际在 `ccr_rate` 库内可省。自检断言全绿后再起后端。

## 十一、前端静态与 nginx 反代（含 HTTPS）

### 11.1 生产 nginx 配置

**新建 `frontend/nginx-prod.conf`**（compose 挂载覆盖镜像内默认 conf）：

```nginx
# 生产 nginx:80 跳 443 + 443 反代后端(无证书可先只保留 80 server,去掉 ssl 段)

# HTTP → HTTPS 跳转
server {
    listen 80;
    server_name _;
    # 若暂未启用 HTTPS,把以下 443 段合并进本 server 即可(删除 return 301)
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    http2 on;
    server_name _;
    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;

    root /usr/share/nginx/html;
    index index.html;

    client_max_body_size 20m;

    # 后端 API 代理(compose 内网,变量形式避免容器重建后 502)
    location /api/ {
        resolver 127.0.0.11 valid=5s ipv6=off;
        set $upstream http://backend:8080;
        rewrite ^/api/(.*)$ /$1 break;
        proxy_pass $upstream;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto https;
    }

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # index.html 不缓存(版本更新后浏览器能拿到新入口);带 hash 静态资源可长缓存
    location = /index.html {
        add_header Cache-Control "no-cache, no-store, must-revalidate";
    }
}
```

### 11.2 HTTPS 必要性说明

- 生产若用 `http://IP` 访问，页面**不是 secure context**，`crypto.randomUUID()` 会抛错，曾导致审批/提交按钮失效（根因 2026-08-21 已定位，前端已加兜底）。
- 上线 HTTPS 后该场景彻底规避，并满足生产安全要求。证书文件放 `./certs/`（`fullchain.pem` + `privkey.pem`）。

## 十二、启动与健康检查

```bash

# 后端健康检查

# 期望:{"code":200,...,"status":"UP"}

# 前端
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/      # 200(HTTPS 则 -k https://localhost/)
```

**流程三表验证（关键出口条件，08-21 事故复盘）**：灌库后三表为**空属正常**——后端首次启动时 `StandardFlowInitializer`（ApplicationRunner）→ `ensureStandardFlow()` → `createFlow()` 会通过 Warm-Flow `importDef` 从节点 skipList 创建流程定义、节点与跳转（测试库实证：`flow_definition=2`、`flow_node=13`、`flow_skip=11`，均由后端启动填充，非增量 SQL）。

```bash
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' -N -e "
SELECT CONCAT('flow_definition=', COUNT(*)) FROM ccr_rate.flow_definition WHERE is_publish=1;
SELECT CONCAT('flow_node=', COUNT(*)) FROM ccr_rate.flow_node;
SELECT CONCAT('flow_skip=', COUNT(*)) FROM ccr_rate.flow_skip;

# 期望:flow_definition=2、flow_node>=13、flow_skip>=6(两套流程 rate_approval + deposit_approval)
```

> 若三表仍为空：检查后端日志 `logs/ccr-run.log` 中 StandardFlowInitializer 是否报错；确认数据库连接无误、`ccr_rate` 库可写。

## 十五、回滚预案

| 场景 | 动作 |
| --- | --- |
| 后端/前端不可用 | 回退镜像/jar/dist：`docker compose -f docker-compose.prod.yml up -d --force-recreate backend frontend`（挂旧镜像 tag） |
| 业务数据异常 | **恢复备份**（§三 C1；重建前为最终一致性快照，重建后仅能回到备份时刻） |
| 数据库 DDL 回滚 | **DDL 不回滚**（`prod_full.sql` 内全部为新库脚本；若已产生真实业务数据，只能恢复备份） |
| 配置错误 | 修正 `config/application-prod.yml` / `.env` 后 `docker compose -f docker-compose.prod.yml restart backend` |
| 演练要求 | 全流程演练 ≤30 分钟（含备份恢复） |

**备份命令（重建前执行）**：
```bash
docker exec ccr-prod-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --single-transaction --routines --triggers --default-character-set=utf8mb4 ccr_rate' > ccr_rate_backup_$(date +%Y%m%d_%H%M).sql
gzip -t ccr_rate_backup_$(date +%Y%m%d_%H%M).sql   # 校验完整性 OK
# 建议再 cp 一份到独立磁盘
```

## 十六、安全边界与运维

1. **严禁入库/外泄**：`db/prod_full.sql`、`db/publish_full.sql`、`db/08_system.sql`、`db/03f_node_assignee.sql`、`config/application-prod.yml`、`.env`——均含真实用户/机构/密码，`.gitignore` 已覆盖，只存本机/生产。
2. **git 约定**：显式路径 `git add`；全中文 commit message + `Co-Authored-By: Claude <noreply@anthropic.com>`；**绝不 push** 上述敏感文件。
3. **账号安全**：全量重建后所有账号初始密码 `Yxnsh@1a3s`、`pwd_change_flag='1'` **首登强制改密**；生产不可跳过；定期轮换 `ccr_prod`/root/Redis 密码。
4. **监控**：`logs/`（ccr-run.log）挂载落盘；`ccr_error_log` 表由 `ccr.run-log` 异步采集（ERROR 起、保留 30 天、每日 03:22 清理）；缓存刷新 cron 兜底（每小时数据、每分钟配置）。
5. **备份策略**：定期 mysqldump（含 `--routines --triggers`）异地保存；Redis `--appendonly yes` 持久化。
6. **外部配置生效**：改 `config/application-prod.yml` 需 `restart backend`；`spring.config.additional-location` 为 `optional:file:./config/`，目录缺失会静默跳过（注意排查）。
7. **运维排障线索**：容器内 `docker compose -f docker-compose.prod.yml logs -f backend`；`/health` 不通先查 mysql/redis 是否 healthy 与 `./config` 挂载是否生效。
