# 数据库表结构增量说明(v2.0.0 之后)

> 版本基线：**v2.0.0**(git tag v2.0.0 = commit `a1fbac9`，2026-08-28 封存)
> 覆盖范围：v2.0.0 封存之后(2026-08-28 至今)所有 db 结构变更，共 **3 个增量脚本、1 张新表、7 个新列、1 个列可空调整、1 个新索引、2 个字典类型**

## 一、新增表(1 张)

### `ccr_commitment_track` 承诺跟踪表

- 来源：`db/incr/20260829_002_commitment_track.sql`(承诺跟踪 v2，#414)
- 定位：承诺跟踪单表，在途行 + 终态行即历史完成情况，**零定时任务**(结算取 `data_dt <= end_date` 最近批次)
- 关键码值：
  - `status`：`TRACKING` 跟踪中 / `FINISHED_MET` 已完成 / `FINISHED_UNMET` 未完成
  - `target_kind`：`BALANCE` 目标余额 / `COUNT` 笔数 / `RATIO` 比例
  - `unit`：随 target_kind 联动(万元 / 笔 / %)
- 时间基准：`end_date` 取 `ccr_application_commitment.end_date`(唯一时间基准)
- 索引：`uk_track(application_id,metric_code,member_customer_no)`、`idx_track_no`、`idx_track_status`、`idx_track_org`、`idx_track_manager`
- 说明：`org_id`/`manager_id` 显式落库(取申请人机构/客户经理)，不依赖关联查询

## 二、列级变更(2 张表)

### `ccr_application` 整单路由字段(来源 `20260829_001_whole_order_route.sql`，整单交付改造)

新增 **7 列**(整单路由权威落库 ccr_application，审批推进以申请单为准)：

| 列 | 类型 | 含义 |
|---|---|---|
| `route_code` | VARCHAR(64) | 整单路由编码(终审岗位，提交/推进时冻结) |
| `route_chain` | VARCHAR(255) | 整单审批链(JSON 数组；贷款=利率最低分项流程，存款=原流程) |
| `start_node_code` | VARCHAR(64) | 整单审批链首节点编码(提交路由后冻结，贷款/存款恒为 BRANCH_MANAGER) |
| `current_node_code` | VARCHAR(64) | 整单当前节点编码(审批推进以申请单为准) |
| `boundary_rate` | DECIMAL(9,6) | 整单终审节点边界利率(矩阵∩产品硬边界交集，审计溯源) |
| `matched_matrix_no` | VARCHAR(64) | 整单命中的权限矩阵行编号(审计溯源) |
| `dept_code` | VARCHAR(64) | 整单路由命中部门编码(节点审批人归属分流) |

### `ccr_resolution` 整单维度决议(来源 `20260829_001_whole_order_route.sql`)

- 新增列 `application_id` BIGINT NULL(整单维度决议；历史按分项决议为空，兼容读取)
- 新增索引 `idx_resolution_application(application_id)`
- `pricing_item_id` 改为**可空**(整单维度决议不落分项；历史按分项决议保留该列；2026-08-29 实测 RESOLUTION_CREATE 插入报 `Field 'pricing_item_id' doesn't have a default value` 后调整)

## 五、投产注意

- 增量脚本全部**幂等**(INFORMATION_SCHEMA 判断列存在性后动态 DDL / INSERT IGNORE)，可重复执行
- **新库/大版本重新投产**：直接用 `prod_full.sql`(已并入上述全部增量)即可，无需单独跑增量
- **存量库升级**：按 1→2→3 顺序执行三个增量脚本
- 流程三表(ccr_flow_definition 等)由后端启动自动填充(prod compose 已含)，无需手工导入
