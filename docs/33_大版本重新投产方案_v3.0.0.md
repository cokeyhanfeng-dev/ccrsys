> 目标：清掉生产上**所有测试数据**，按 **v3.0.0** 作为新大版本重新投产。
> 基线：生产当前为 **v2.0.0** 代码线 + `db/prod_full.sql`（2026-08-26 生成）数据。
> 配套文档：表结构增量见 `docs/31_数据库表结构增量说明.md`；全库码值见 `docs/32_数据库码值说明.md`；容器化基础流程见 `docs/25_生产全量部署手册.md`（本方案是其**版本升级配套**，冲突处本方案优先）。

## 二、数据清理策略（两条路径）

### 路径 A：全量重建（推荐 · 本方案主路径）

**彻底清空全部测试数据（物理级），表结构/配置/真实主数据全新**。适合「大版本重新投产」语义。

- 执行：`DROP DATABASE ccr_rate` → 重建 → 灌入升级后的 `prod_full_v3.0.0.sql`（§三）
- 优点：无任何历史残留（申请痕迹/流程实例/测试客户/脏数据 100% 清除）；结构与代码版本严格对齐
- 缺点：**不可逆**，必须先完整备份；停机窗口较长
- 前置：完成 §三 prod_full 升级、§五 镜像重建、§四 清数据脚本核对

### 路径 B：存量库清理（备选 · 保留业务数据时用）

在**存量库**上执行 `db/26_clear_test_data.sql`：

- 业务表全部 TRUNCATE（申请/分项/担保/审批/表决/决议/快照/承诺/通知/审计/导出/outbox/变更日志/手工集团 + Warm-Flow 运行数据）
- 数仓测试虚拟客户按编号 DELETE（CUST001-004/101、CUSTP001/002、MEMBER_A/B、REL001、GROUP001）
- **保留**：系统主数据（ccr_sys_user/dept/menu/role/post）、配置表（dict/matrix/rule/node_permission/node_assignee/product/lpr/...）、数仓真实机构（dw_org_dim/performance）、流程定义
- 幂等可重复执行，`FOREIGN_KEY_CHECKS=0` + TRUNCATE
- **前置**：本方案 §四 已补 `ccr_commitment_track` TRUNCATE

> 路径 A 与 B 二选一。若走 A（推荐），§四 的补全仅用于将来增量环境清理，本次不直接使用。

## 三、prod_full 升级（prod_full.sql → prod_full_v3.0.0.sql）

`db/prod_full.sql`（2026-08-26）**不含** v2.0.0 之后任何增量（已核实：无 `ccr_commitment_track`、无 `ccr_application` 整单 7 列、无 `ccr_resolution.application_id`）。

**升级方法**：在 `prod_full.sql` 末尾按依赖序追加 3 个增量脚本（全部幂等，可安全重复执行）：

| 序 | 脚本 | 内容 |
|---|---|---|
| 1 | `db/incr/20260829_001_whole_order_route.sql` | `ccr_application` +7 列(route_code/route_chain/start_node_code/current_node_code/boundary_rate/matched_matrix_no/dept_code)；`ccr_resolution` +application_id、+idx_resolution_application、pricing_item_id 改可空 |
| 2 | `db/incr/20260829_002_commitment_track.sql` | 新表 `ccr_commitment_track`(承诺跟踪 v2)；字典 `ccr_commitment_target_kind` |
| 3 | `db/incr/20260901_001_commitment_track_metric_name.sql` | 回刷 metric_name 中文名(重建后无存量，可跳过) |

**生成**（构建机执行，产物只放部署侧，**严禁入库/上传**）：
```bash
cd <部署目录>
cat db/prod_full.sql \
    db/incr/20260829_001_whole_order_route.sql \
    db/incr/20260829_002_commitment_track.sql \
    db/incr/20260901_001_commitment_track_metric_name.sql \
    > prod_full_v3.0.0.sql
```

**自检断言更新**（替代 docs/25 §5.3）：

| 断言 | v2.0.0 期望 | **v3.0.0 期望** |
|---|---|---|
| 表数 | 102 | **103**（+ccr_commitment_track） |
| `ccr_sys_user` | 约 79 | 约 79（不变） |
| `ccr_product_rate_limit` | 2 | 2（硬边界，load-bearing） |
| `ccr_rate_rule_set`/`ccr_rate_rule` | 0 | 0 |
| `ccr_commitment_track` | 不存在 | **存在**（空表） |
| `ccr_application` 整单 7 列 | 不存在 | **存在** |
| `ccr_resolution.application_id` | 不存在 | **存在** |
| 流程三表 | 空属正常 | 空属正常（后端启动填充） |

## 六、执行步骤（衔接 docs/25 §十～§十二）

> 前置：完成 §三 prod_full_v3.0.0.sql、§五 新镜像；`.env`（MYSQL_ROOT_PASSWORD/REDIS_PASSWORD）、`config/application-prod.yml`（prod 外部配置，不入库）就位。

```bash
cd <部署目录>   # 含 docker-compose.prod.yml 与 .env

# 0. 备份(全量重建不可逆,务必先做)
docker exec ccr-prod-mysql sh -c 'exec mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --all-databases' > backup_prod_pre_v3.0.0_$(date +%Y%m%d%H%M).sql

# 1. 起 MySQL / Redis(仅内网)
docker compose -f docker-compose.prod.yml up -d mysql redis
docker compose -f docker-compose.prod.yml ps   # 等 healthy

# 2. 清空旧库(路径 A 全量重建)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" -e "DROP DATABASE IF EXISTS ccr_rate; CREATE DATABASE ccr_rate CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"'

# 3. 灌入 v3.0.0 全量
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" --default-character-set=utf8mb4 ccr_rate' < prod_full_v3.0.0.sql

# 4. 应用账号(§六/§十.4;如用 root 跳过)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' <<'SQL'
CREATE USER IF NOT EXISTS 'ccr_prod'@'%' IDENTIFIED BY '<APP_PASSWORD>';
GRANT SELECT, INSERT, UPDATE, DELETE, EXECUTE ON ccr_rate.* TO 'ccr_prod'@'%';
FLUSH PRIVILEGES;
SQL

# 5. 自检(§三 断言表,核心几条)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' -N -e "
SELECT CONCAT('tables=', COUNT(*)) FROM information_schema.TABLES WHERE TABLE_SCHEMA='ccr_rate';
SELECT CONCAT('commitment_track=', COUNT(*)) FROM information_schema.TABLES WHERE TABLE_SCHEMA='ccr_rate' AND TABLE_NAME='ccr_commitment_track';
SELECT CONCAT('route_code_col=', COUNT(*)) FROM information_schema.COLUMNS WHERE TABLE_SCHEMA='ccr_rate' AND TABLE_NAME='ccr_application' AND COLUMN_NAME='route_code';
SELECT CONCAT('users=', COUNT(*)) FROM ccr_rate.ccr_sys_user;
SELECT CONCAT('rate_limit=', COUNT(*)) FROM ccr_rate.ccr_product_rate_limit;
"
# 期望:tables=103、commitment_track=1、route_code_col=1、users=79、rate_limit=2

# 6. 清 Redis 旧缓存
docker exec ccr-prod-redis redis-cli -a "$(grep '^REDIS_PASSWORD=' .env | cut -d= -f2-)" FLUSHDB

# 7. 起全部服务(自动拉起 backend → 等 mysql/redis healthy)
docker compose -f docker-compose.prod.yml up -d

# 8. 健康检查
curl -s http://localhost:8080/health                     # {"code":200,...,"status":"UP"}
curl -s -o /dev/null -w "%{http_code}\n" http://localhost/   # 200(HTTPS: -k https://localhost/)

# 9. 流程三表验证(后端启动填充,灌库后空属正常)
docker exec -i ccr-prod-mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' -N -e "
SELECT CONCAT('flow_definition=', COUNT(*)) FROM ccr_rate.flow_definition WHERE is_publish=1;
SELECT CONCAT('flow_node=', COUNT(*)) FROM ccr_rate.flow_node;
SELECT CONCAT('flow_skip=', COUNT(*)) FROM ccr_rate.flow_skip;
"
# 期望:flow_definition=2、flow_node>=13、flow_skip>=6

# 10. HTTPS 生效确认(crypto.randomUUID 需 secure context,防审批按钮失效)
#     http://IP 访问会导致 2026-08-21 那类按钮失效;确认 443 证书/反向代理就绪
```

## 八、回滚预案

- **数据库**：全量重建不可逆 → 备份 `backup_prod_pre_v3.0.0_*.sql` 保留；回滚 = 重建 + 灌入备份
- **镜像**：回退 `docker-compose.prod.yml` image tag 到 `ccr-backend:20260826`/`ccr-frontend:20260826` 后重新 up；代码 v3 数据若已产生，回退仅影响新功能（整单/承诺跟踪 v2），历史数据结构仍兼容（增量均为加列/加表，未删改旧列）
- **数据侧风险**：`ccr_resolution.pricing_item_id` 改可空、`ccr_application` 加列均为向后兼容变更，无破坏性 DDL
