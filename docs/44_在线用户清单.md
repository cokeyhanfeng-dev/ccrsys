# 在线用户清单

## 使用方式

管理员登录 PC 后打开「系统管理 → 在线用户」（`/system/online`）。按人员聚合展示工号、姓名、机构、当前主角色、在线终端、最近登录及访问时间、有效会话数；展开人员行查看各次会话的终端、登录时间、最近访问和 IP。支持工号/姓名关键词、机构精确匹配、终端筛选及按人数分页。查询、重置和手动刷新都会重新获取会话快照。

默认查询全部终端，每个账号一行；同一人有多次移动登录或电脑/移动同时登录，只增加该行的会话数，展开保留各次真实会话。最近登录为该行会话中最新登录时间，最近访问取最大值，列表按最近访问倒序，无时间的旧会话在末尾。

顶部展示符合当前筛选条件的人数/会话数，以及姓名和机构范围内的电脑端、移动端人数/会话数。两类终端概况不受终端筛选和分页限制，可以点击切换终端；同一账号可能同时计入两类终端，两类人数相加不等于去重总人数。选择移动端时，列表和展开明细仅展示符合条件的移动会话。提供管理员账号级强制下线，登录并发策略保持。

## 在线口径

- 会话由 Sa-Token 和 Redis 现有数据判断：登录映射仍有效、未超过绝对有效期/空闲有效期，且本地账号仍启用、未删除。
- 关闭页面不会立即注销会话；最近访问时间包含页面自动请求，不代表人员正在手动操作。
- 仓库默认会话总有效期为 86400 秒，空闲有效期 7200 秒；实际以部署配置为准。
- PC 主动退出先调用 `/auth/logout` 注销当前会话，成功后清理本地身份并跳转登录；网络失败保留身份供重试。移动端已有注销调用，不改变其协议。
- 账号级会话和 Token 会话区分：新增登录时间、IP 写入各自 TokenSession，多端登录不相互覆盖。
- 上线前已存在的会话可以列出，但缺失登录时间/IP 时展示「—」，不把查询时间当作登录时间。下次登录时补齐。
- 会话列表是查询时快照；读取期间退出、登录会使总数短暂变化，可手动刷新。请求结束后发生的退出不追溯修改已显示列表。

## 接口与权限

`GET /system/online-users`，仅 `admin` 可访问，沿用 `/system/**` 拦截器并增加控制器注解和服务内角色校验。响应 `Cache-Control: no-store`。

| 参数 | 含义 |
| --- | --- |
| pageNum | 页码，默认 1，最小 1 |
| pageSize | 每页数量，默认 20，范围 1～100 |
| keyword | 工号/姓名关键词，最多 64 字符，去除首尾空白后匹配 |
| orgId | 机构 ID，正数；只匹配该机构 |
| client | PC / MOBILE，省略或空值为全部 |

返回统一 `R`，data 包含 `total`、`userCount`（均为筛选后的去重人数）、`sessionCount`（筛选后的会话数）、`pcUserCount/mobileUserCount`、`pcSessionCount/mobileSessionCount`（姓名和机构范围内、终端筛选前的统计）、`records`、`queriedAt`。按人员聚合后分页，单人的会话不会跨页。

人员行包括 userId/username/nickName/orgName/roleName、clients、sessionCount、lastLoginTime、lastAccessTime、sessions。sessions 保留每个符合条件的会话的 client/loginTime/lastAccessTime/loginIp 及人员展示字段。响应不返回 token、TokenSession、Redis key 或密码。角色展示本地账号当前主角色。

2026-09-22 聚合优化调整了 total/records 契约，后端和 PC 前端必须配套发布。

Redis 只使用当前 StpLogic 生成的登录 token 前缀，通过 SCAN 枚举并去重，再读取有效期和会话元数据；查询不建立 TokenSession、不刷新会话活跃时间、不续期。避免使用 Sa-Token 1.38 默认搜索内部的 KEYS。最多读取 20000 个去重 token key，超过上限明确报错，禁止把截断结果展示成完整人数。用户/角色/机构按去重账号每 500 个批量读取。Redis 或数据库失败时接口报错，前端显示加载失败，不把故障显示为零人在线。

## 管理员强制下线（2026-09-22）

- 每个人员行提供“强制下线”，二次确认明确注销该账号全部电脑端和移动端会话，包含当前筛选未显示的会话。未保存内容可能丢失。当前管理员账号禁用该按钮，服务端也拒绝该目标；本人使用右上角退出登录。
- `POST /system/online-users/{userId}/kickout`，userId 正整数、目标账号须存在；沿用拦截器、控制器 admin 注解及服务端角色校验。返回 R<Void>、Cache-Control: no-store，不接收或返回 token。
- 使用 Sa-Token `kickout(userId)` 对现有会话执行账号级下线；被下线用户下一次请求返回 401，PC/移动端走现有会话失效处理。其他账号不受影响，不修改账号启停状态和审批数据；用户可以重新认证登录，此操作不封禁账号。
- 操作日志类型 FORCE_LOGOUT（审计页面显示“强制下线”），记录管理员、目标用户编号、操作时间、全终端范围及结果。数据库先记录请求，再操作 Redis，再更新结果；初始日志失败不执行下线，Redis 异常提示可能部分生效，完成后日志更新失败明确提示“已执行”。不使用数据库回滚掩盖已执行的 Redis 副作用。
- 前端防重复点击，不自动重试下线请求，成功及异常后均刷新清单核对。已无会话的账号执行为空操作；之后重新登录产生的新会话不属于已完成的下线操作。
- 更新后端及 PC，无 DDL，无需更新移动静态资源。未执行生产踢人操作。

本轮聚合及强制下线验证：`./dev verify` 后端 571 项、PC 37 项、移动端 42 项通过，两端构建成功。`./dev app-up` / `./dev smoke` 报 Docker Desktop 未运行，真实 Redis 与浏览器验收未执行，数据卷未重建。
