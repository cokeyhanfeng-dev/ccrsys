## 三、增量发布规则(自 v1.0 起)

1. **增量 SQL**:改库一律新增 `db/incr/<YYYYMMDD>_<NNN>_<描述>.sql`(规范见 `db/incr/README.md`):
   - 幂等可重跑(`IF NOT EXISTS` / `ON DUPLICATE KEY` / UPDATE 加状态条件)
   - 涉及规则/矩阵/缓存类配置的改动,尾部注释给出需清理的 Redis key
   - **只追加,不修改、不删除**已发布的增量脚本
2. **增量代码打包**:`scripts/incr-release.sh <序号如 001> [增量SQL文件...]` → 产出 `release/incr_<日期>_<序号>/`:
   ```
   release/incr_<日期>_<序号>/
     README.md              # 部署/验证/回滚说明 + 本轮改动清单
     db/*.sql               # 本次增量 SQL
     backend/ccr-admin.jar  # 后端增量 jar(整体替换)
     frontend/dist/         # 前端增量静态包(整体替换)
   ```
3. **部署顺序**:先执行增量 SQL(含按提示清理 Redis)→ 替换后端 jar → 替换前端 dist。
4. **入库范围**:`release/` 打包产物不入库;`db/incr/` 增量 SQL 入库跟踪;每批增量在下方台账追加一行。
