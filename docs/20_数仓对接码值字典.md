# 数仓对接码值字典（集团申请 / 客户申请）

> **用途**：数仓推送各字段时应遵循的**码值/格式规范**——当数仓提供某字段数据时，用什么编码值、什么格式，系统才能正确识别与展示。
> **范围**：集团补录（新增集团/手工补录成员）＋ 客户申请带出（对公/对私/集团链/融资合同）涉及的全部码值字段。
> **数据来源**：代码实测（`frontend/src/utils/dict.ts` 展示字典、`DataWarehouseService`/`CustomerController` 数仓查询字段映射）+ 测试库造数实际值（2026-08-20 查询）。
> **契约基准**：表结构见 `docs/15_数仓数据需求清单.md`；本文档补充其**码值枚举**。
> **版本**：v1.1 / 2026-08-20（含数仓回执确认，见 §八）

## 二、证件类型 `cert_tp`

**数仓已回执**：对公统一 `USCC`，对私统一 `IDC`。

系统已登记的全部证件类型编码（`dict.ts` CERT_TYPE / certTypeText），数仓推送落在表内即正确显示：

| 编码 | 中文 | 适用 | 状态 |
|---|---|---|---|
| `USCC` | 统一社会信用代码 | 对公 | ✅ 数仓确认使用 |
| `UNIFIED` | 统一社会信用代码 | 对公 | 兼容（测试库旧值） |
| `UNIFIED_SOCIAL` | 统一社会信用代码 | 对公 | 兼容 |
| `IDC` | 身份证 | 对私 | ✅ 数仓确认使用 |
| `RDC` | 居民身份证 | 对私 | 兼容 |
| `ID` | 身份证 | 对私 | 兼容（测试库旧值） |
| `ID_CARD` | 身份证 | 业务库编码 | 兼容 |

> **给数仓的要求**：对公提供 `USCC`，对私提供 `IDC`；未收录的编码会**原样透传显示**（例如传 `CERT_B` 页面直接显示 "CERT_B"）。若有新编码，先与开发同步登记。

## 三、对公客户主数据 `caps_corp_cust_basic_info`（集团补录＝对公全套要素）

集团补录表单（`groupSupplement`）与普通对公申请的"对公全套"字段一一对应，**码值要求与数仓推送口径完全一致**：

| 补录/带出字段 | 数仓物理列 | 数仓提供值（码值/格式） | 前端录入方式 |
|---|---|---|---|
| 统一社会信用代码 | `cert_no` + `cert_tp=USCC` | 18 位统一社会信用代码（GB 32100-2015） | 补录：文本框（可空） |
| 五级分类 | `ffthlv_class` | **`010` 正常 / `020` 关注 / `030` 次级 / `040` 可疑 / `050` 损失** | **补录：下拉（010-050，可空）** |
| 内部信用等级 | `crdt_grd` | 字母评级（AAA/AA/A/BBB/BB/B 含 ± 变体），**直接透传** | 补录：文本框（可空） |
| 所属行业 | `blgd_idsty` | **中文行业名（直接透传）** | 补录：文本框（可空） |
| 注册资本(万元) | `rest_asts` | DECIMAL(18,4)，单位**万元** | 补录：数字框（可空） |
| 开户机构 | `openact_org_nm` | 机构中文名（或编号 `openact_org_no`） | 补录：文本框（可空） |
| 开户日期 | `openact_dt` | DATE `yyyy-MM-dd` | 补录：日期框（可空） |
| 基本户账户 | `basic_account_no` | 账户号明文 | 补录：文本框（可空） |
| 企业性质 | `entp_charic` | SOE / NON_SOE | 数仓带出（只读） |
| 企业规模 | `entp_scale` | 大型/中型/小型/微型 | 数仓带出（只读） |
| 客户分类 | `cust_class` | EXISTING / NEW | 数仓带出（只读，决定存量/新增） |

> 客户姓名 `cust_name`、客户号 `cust_no`、证件号 `cert_no` 为纯文本，无码值要求。

## 五、集团链快照（集团申请带出）

### 5.1 集团主数据 `dw_customer_group_snapshot`

| 字段 | 数仓提供值 | 系统处理 | 备注 |
|---|---|---|---|
| `group_type` 集团类型 | `INDUSTRY_GROUP` | 原样展示 | 集团补录固定此值；新增集团时系统写 `INDUSTRY_GROUP` |
| `manager_org_id` 主办机构 | 机构编号（字符串） | 原样 | 前端未展示（补录未录入） |
| `group_status` 集团状态 | **`NORMAL` 正常 / `DISSOLVED` 解散** | 展示字典已对齐，均显示中文 | 数仓已确认；系统按 `relation_end` 判定成员在团，不按此阻断 |

### 5.2 集团成员 `dw_customer_group_member_snapshot`

| 字段 | 数仓提供值 | 系统处理 | 备注 |
|---|---|---|---|
| `member_role` 成员角色 | CORE 核心 / GENERAL 一般 | 页面 CORE→核心，其余→一般 | 补录下拉固定 CORE/GENERAL |
| `control_relation` 控制关系 | 中文（控股/参股等） | 原样透传 | 自由文本 |
| `is_core_member` | Y / N | 数仓空时按 member_role=CORE 推导 | 二者其一即可 |
| `relation_start` 入团日期 | DATE | 展示 | 空=在团 |
| `relation_end` 退团日期 | DATE（**空=在团**） | **成员有效校验基准**：空或不早于当日＝在团；早于当日＝已退团 BLOCK | 新增集团豁免此校验 |

> 成员**名称不落数仓成员表**——由 `member_customer_no` 反查 `caps_corp_cust_basic_info.cust_name`；查不到则页面显示"暂无数据"，需手工补录成员名。

### 5.3 集团授信 `dw_group_credit_snapshot`

| 字段 | 数仓提供值 | 系统处理 |
|---|---|---|
| `credit_status` | 按数仓原值**直接透传** | EFFECTIVE/EXPIRED/CLOSED 显示中文；FROZEN 原样显示（已确认接受） |
| `currency` | ISO 4217 | 中文映射 |
| `revolving_flag` | Y / N | 快照展示 |
| 各额度字段 | DECIMAL(18,4) 万元 | 仅展示参考，勾稽基准读 group_info_json 申请额度 |

### 5.4 成员额度 `dw_member_credit_limit_snapshot`

| 字段 | 数仓提供值 | 系统处理 |
|---|---|---|
| `allocation_mode` | EXCLUSIVE 独占 / SHARED 共享 | 快照展示 |
| `limit_status` | EFFECTIVE / EXPIRED / FROZEN | 有效优先排序（查最新批次） |
| `allocated_amount` 分配额度 | DECIMAL(18,4) 万元 | 申请页成员表"分配额度"列 |

## 六、融资 / 合同 / 存款快照

| 表 | 字段 | 码值 | 系统展示字典 |
|---|---|---|---|
| dw_loan_contract_snapshot | `guarantee_type` 担保主类型 | MORTGAGE 抵押 / PLEDGE 质押 / GUARANTEE 保证 / CREDIT 信用 | 4 主类型全收录 |
| dw_loan_contract_snapshot | `contract_status` | EFFECTIVE 有效 / SETTLED 结清 / OVERDUE 逾期 | 全收录（含徽标） |
| dw_loan_note_snapshot | `note_status` | NORMAL 正常 / SETTLED 结清 / OVERDUE 逾期 | 全收录（含徽标） |

## 七、手工补录表单码值规范（集团 / 成员补录）

> 新增集团（数仓未收录）就地补录，**补录值按数仓同口径**，确保未来数仓收录后口径一致。

**集团补录（`groupSupplement`）**：

| 字段 | 码值/格式要求 |
|---|---|
| 集团编号 | 与数仓不重复（数仓查重自动归存量，不重复则补录生效）；纯文本 |
| 集团名称 | 必填，纯文本 |
| 统一社会信用代码 | 18 位（建议按 GB 32100-2015），可空 |
| 五级分类 | **下拉：010 正常/020 关注/030 次级/040 可疑/050 损失**，可空 |
| 信用等级 | 字母评级，直接透传，可空 |
| 行业 | 中文行业名，可空 |
| 注册资本 | 数字，单位万元，可空 |
| 开户机构/日期/基本户 | 文本/日期，可空 |
| 集团类型 | **固定 `INDUSTRY_GROUP`**（前端隐藏默认，不可选） |
| 币种 | 固定 `CNY`（前端隐藏默认） |
| 本次申请额度 | 必填，>0，单位万元；勾稽基准（成员申请金额合计 ≤ 此额度） |

**成员补录（`supplementMembers`）**：

| 字段 | 码值/格式要求 |
|---|---|
| 成员客户号 | 必填；若数仓已收录同号成员则并入数仓成员（不落手工表） |
| 成员名称 | 必填，纯文本 |
| 统一社会信用代码/五级分类(下拉)/信用等级/行业/注册资本/开户机构/开户日期/基本账户 | 同集团补录口径，可空 |
| 成员角色 | 下拉固定 `CORE` 核心 / `GENERAL` 一般（默认 GENERAL） |
| 控制关系 | 中文（控股/参股等），可空 |
| 关系起止 | DATE，**空=在团**（relation_end 早于当日＝已退团） |

## 八、数仓回执确认结论（2026-08-20）

数仓侧已对码值口径逐项回执确认，系统侧同步落实：

| # | 字段 | 确认结论 | 系统侧落实 |
|---|---|---|---|
| 1 | `group_status` 集团状态 | **NORMAL 正常 / DISSOLVED 解散** | 展示字典已从 NORMAL/ABNORMAL/CLOSED 改为 NORMAL/DISSOLVED，推送 DISSOLVED 显示中文"解散" |
| 2 | `cert_tp` 证件类型 | **对公 USCC / 对私 IDC** | 系统已兼容（USCC/IDC 均收录），无需改动 |
| 3 | `ffthlv_class` 五级分类 | **010 正常 / 020 关注 / 030 次级 / 040 可疑 / 050 损失** | 新增五级分类数字码字典；补录表单（集团/成员/对公）改为下拉 010-050；数仓带出、审批详情、档案展示统一映射中文 |
| 4 | `blgd_idsty` 行业 | **维持中文行业名** | 系统原样透传，无需改动 |
| 5 | `crdt_grd` 信用等级 | **无统一字典，直接透传** | 系统原样透传，无需改动 |
| 6 | `credit_status` 授信状态 | **直接透传** | 维持现状（EFFECTIVE/EXPIRED/CLOSED 显示中文，FROZEN 原样显示） |
| 7 | `mrrg_sittn` 婚姻状况 | **中文直接透传** | 系统兼容中文/英文码，页面显示中文，无需改动 |
| 8 | `currency` 币种 | **直接透传，下拉菜单暂时维持现有 5 种**（CNY/USD/HKD/EUR/JPY） | 维持现状 |

> 系统侧改动已提交代码：`dict.ts`（group_status 字典对齐 + 新增五级分类字典）、`loan.vue`（集团/成员补录 + 对公五级分类改下拉、回填归一化）、`approval/detail.vue`、`history/archive.vue`、`deposit.vue`（五级分类展示映射/下拉）。
