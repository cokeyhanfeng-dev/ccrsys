# 移动端上线前接口校验（2026-09-12）

## 结论与边界

移动前端已经调用正式 CCR 接口，业务查询和审批复用电脑端的数据库及领域服务。本轮使用真实 HTTP、MySQL、Redis 执行移动接口回归，覆盖两种免密身份源、六类审批角色、整单审批/表决/行长决策和数据库附件。发现的问题已修复；应使用本轮更新后的后端、移动静态文件和独立 Nginx 配置进入联调。

**满足代码和隔离环境联调条件；生产网络、真实 OA/有度和手机附件尚未验收。** 网络放通后仍需按本文末尾的顺序完成上线测试。外部验票回归使用本机虚构服务，不能代替真实平台验票成功、有效期、应用绑定与一次性消费的证据。

## 请求链路与接口核对

浏览器只请求移动站点同源路径：`/mobile/api/mobile/...` → Nginx → CCR 后端 `/mobile/...`。业务链路不经过 Magic API；附件从 CCR 数据库经后端返回，手机无需连接数据库或存储桶。

下表中的路径相对 CCR 后端 `/mobile`。JSON 接口采用统一 `R`；附件成功为二进制并携带 `Content-Disposition`。

| 接口 | 本次验证内容 |
|---|---|
| POST `/login` | 有度原生 token 经真实验票客户端调用本机 HTTP 服务，再映射本地账号、签发移动会话；JS 安卓/iOS 桥协议另有单测，并与 digitalDashboard 代码核对 |
| POST `/oa/login` | ticket 经 HTTP 验票，核对应用认证头、纯文本账号、本地主角色与状态；过期/无票据拒绝 |
| GET `/session`、POST `/logout` | 六类角色会话恢复、账号停用、退出后失效；电脑 token 与移动 token 跨端访问拒绝 |
| GET `/tasks` | 普通审批、本人委员会席位、行长待决策的真实 SQL 和响应；委员显示当前审批利率 |
| GET `/done?page&size` | 普通审批、本人匿名票哈希和行长决策的合并查询；本人经办对象详情可回看；非法分页拒绝 |
| GET `/messages` | 当前会话接收人过滤，伪造 recipientId 无效；他人的测试消息不可见 |
| GET `/applications/{id}` | 多分项、申请版本、客户信息、附件元数据；跨支行拒绝、秘书历史范围、委员票数和结果脱敏 |
| POST `/approve`、`/reject` | 整单推进/否决、逐项 1 BP、空调价保留原链路、申请版本冲突、并发只提交一次、重复键拒绝、移动渠道留痕；秘书/存款禁止调价 |
| POST `/vote-rounds/{roundId}/ballots` | 六个本人席位提交、整单计票、重复票拒绝、非本批委员拒绝、否决票导致整单否决；存款支行审批可创建小组批次 |
| POST `/decisions` | 行长整单同意和一票否决，逐分项落库，重复决策拒绝 |
| GET `/vote-rounds/{roundId}/opinions` | 行长读取匿名意见，委员拒绝 |
| GET `/applications/{id}/attachments/{fileId}` | 从数据库读取 PDF 字节并比对、认证头、缓存响应头、跨申请附件及跨支行对象拒绝 |

前端另校验：长整数 ID 不失真、审批版本及幂等键透传、同分项多合同去重、1 BP 小数精度、OA 回调清理、401 清会话、异常结果提示、附件格式识别和补录融资合并。

## 本次修复

1. **版本号未实际校验。** 原整单审批服务接收 `versionNo` 后未比较，本机 HTTP 已复现旧版本仍提交成功。新增 `MobileApprovalCommandService`：先校验对象权限，在事务内锁定申请并复核版本，调用既有服务成功后递增申请版本。旧页面和第二个并发请求返回 1010，失败回滚无动作记录。
2. **秘书已办详情被拒绝。** 主角色秘书办理后，申请离开秘书节点，已办列表有记录但详情返回 403。补齐有本人真实审批轨迹的历史查看权限，未经办对象仍拒绝；兼岗口径保留。
3. **空调价触发重算。** 前端没有改变利率时会提交空对象；移动适配现在将空集合按未调价处理，沿用冻结链路。同时在服务端拒绝秘书与存款业务携带调价内容。
4. **委员待办利率滞后。** 原待办 SQL 只返回申请初始利率；补充 `currentApprovalRate`，卡片与详情采用当前审批利率。
5. **材料遗漏人工融资。** 详情接口将数仓融资和申请补录分别返回；移动页面现在合并 `otherLoans/appOtherLoans`。同机构去重仍由原详情服务执行。
6. **代理异常响应误判。** HTTP 200 空对象/缺少业务 code 的 JSON 不再视为成功；HTML、空响应与附件代理回退页面明确报错。写操作提示结果未确认，保留核对和同键重试能力。
7. **独立站点根路径丢票。** `/?ticket=...` 跳转至 `/mobile/` 时保留参数；服务器级访问日志脱敏，并设置 no-referrer。容器内真实 Nginx 验证了根路径和无尾斜杠两种携票入口。

## 网络开通后必须完成的部署与验收

1. **发布内容齐全。** 后端使用包含本轮修复的新 `ccr-admin.jar`/镜像；移动端发布 `frontend/dist-mobile` 的内容至 Nginx `html/mobile/`。已有 `./dev release 2` 的归档仅包含电脑端 `dist`，不会自动包含独立移动入口。Nginx 使用本轮 `frontend/mobile/nginx.conf`，把示例 `backend:8080` 替换为实际可达后端。独立机器无法直接解析其他机器的 Docker 服务名。
2. **确认三个网络方向。** 手机 → 移动站点；移动 Nginx → CCR 后端；CCR 后端 → 所选身份源验票服务。仓库 Compose 后端映射为 `8080:8080`，电脑前端为 `3000:80`，服务器自定义映射以现场为准。移动站点监听端口由部署方配置，手机只需访问站点端口。
3. **启用正确的免密协议。** 当前移动 OA 接收 `ticket/oaToken`，配置 `CCR_MOBILE_OA_ENABLED/VERIFY_URL/APP_ID/API_KEY`；有度配置 `CCR_MOBILE_YOUDU_ENABLED/VERIFY_URL/SUCCESS_CODE`。这些开关默认 false，网络放通本身不会启用登录。若实际 OA 工作台传递的是 Authing `code`，当前移动入口尚未支持，需补接；电脑端 `/auth/code-login` 的成功不能作为移动成功依据。修改 Compose 环境需重新创建对应后端容器加载，不能只 restart。
4. **真实账号验收。** 各审批角色成功免密，客户经理拒绝、停用账号拒绝；工号精确匹配本地账号；过期/重复/其他应用票据拒绝。并核对任务数与电脑端同一身份一致，机构、节点及兼岗配置正确。不得以临时开放密码入口或信任 URL 的账号字段替代。
5. **真实业务与附件。** 使用指定测试申请完成贷款调价/否决、存款、小组表决和行长决策，核对页面与后台最终状态；测试网络中断后的状态核对。在 Android/iOS 实际有度/OA 容器内分别验证 PDF、图片、Office 下载及大文件、刷新恢复、退出。数据库附件字节回传已本地通过，Blob 下载和 PDF 阅读能力仍取决于客户端；若不支持，需要另接客户端文件打开能力后再验收附件功能。

当前应按以上条件进入上线联调，真实登录与附件通过后再扩大使用范围。
