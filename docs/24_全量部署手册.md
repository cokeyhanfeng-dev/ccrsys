# 全量部署手册(Docker + Nginx)

> **适用范围**:用 Docker 方式对 CCR 系统做**全量部署/重建**(全新环境,或现有增量环境整体重建)。
> 部署架构:`ccr-mysql`(MySQL 8) + `ccr-redis`(Redis 7) + `ccr-backend`(Spring Boot) + `ccr-frontend`(Nginx 托管 Vue3)。
> 与增量部署的区别:增量只补增量 SQL + 替换 jar/dist;**全量 = 清库重建 + 全量基线 + 全部增量 + 最新 jar/dist**。
> **注意**:`publish_full.sql` 只 `CREATE DATABASE IF NOT EXISTS`(不自动 DROP 旧库),全量重建**必须先手动 DROP 旧库**,否则旧表残留导致结构不一致。

---

## 一、部署包准备

| 内容 | 来源 | 说明 |
| --- | --- | --- |
| 全量基线 SQL | `db/publish_full.sql` | 建库 + 96 表 + 系统/机构/规则/矩阵/数仓种子,`CREATE IF NOT EXISTS` 幂等 |
| 增量 SQL(全部) | `db/incr/*.sql`(10 个) | 按文件名升序执行,幂等可重复 |
| 后端 jar | `release/incr_20260821_022/backend/ccr-admin.jar` | **最新全量构建**,内含 019-022 全部代码 |
| 前端 dist | `release/incr_20260821_022/frontend/dist/` | 最新静态包 |
| 数仓 mock(仅测试) | `db/10_mock_external.sql` / `15_test_data.sql` / `17_test_data_latest.sql` | 生产**不执行**(数仓真实推送) |

> 若后续有更新增量包,用最新的 release/incr_* 产物替换 jar/dist,并新增执行对应增量 SQL。

## 二、场景 A:现有 docker 环境 → 全量重建(推荐)

### 第 0 步:备份(重建不可逆,强烈建议)
```bash
docker exec ccr-mysql mysqldump -uroot -proot123 --single-transaction --default-character-set=utf8mb4 ccr_rate > ccr_rate_backup_$(date +%Y%m%d).sql
```

### 第 1 步:重建空库
```bash
docker exec ccr-mysql mysql -uroot -proot123 -e "DROP DATABASE IF EXISTS ccr_rate; CREATE DATABASE ccr_rate CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"
```

### 第 2 步:执行全量基线
```bash
docker exec -i ccr-mysql mysql -uroot -proot123 --default-character-set=utf8mb4 < db/publish_full.sql
```

### 第 3 步:按文件名升序执行全部增量 SQL
```bash
for f in db/incr/*.sql; do
  echo "==> $f"
  docker exec -i ccr-mysql mysql -uroot -proot123 --default-character-set=utf8mb4 < "$f"
done
```

### 第 4 步:清 Redis(旧缓存 key 可能残留)
```bash
docker exec ccr-redis redis-cli FLUSHDB
```

### 第 5 步:替换后端 jar + 重启
```bash
docker cp release/incr_20260821_022/backend/ccr-admin.jar ccr-backend:/app/app.jar
docker restart ccr-backend
```

### 第 6 步:替换前端 dist + 重载 nginx
```bash
docker exec ccr-frontend rm -rf /usr/share/nginx/html/assets /usr/share/nginx/html/index.html
docker cp release/incr_20260821_022/frontend/dist/. ccr-frontend:/usr/share/nginx/html/
docker exec ccr-frontend nginx -s reload
```

## 三、场景 B:全新环境(无任何容器)

> ⚠️ `docker compose up` 首次启动会由 mysql 镜像 initdb 自动执行 `./db` 挂载目录下全部拆分脚本(26 个,字母序 01→26),**其中包含测试数据(10/15/17/22/26)**——**生产不适用**。生产全新环境仍按场景 A 手动执行(第 1-3 步)。

测试环境全新起:
```bash
docker compose up -d --build
# 空卷首次启动:initdb 自动建全库 + 种子 + mock 数据;后端镜像内编译,前端 nginx 托管
```

## 六、注意事项与回滚

1. **重建会清空全部业务数据**(申请/审批/承诺/操作记录),执行第 1 步前务必确认第 0 步备份成功。
2. **jar 必须用最新全量构建**(`release/incr_<最新>/backend/ccr-admin.jar`),内含截至打包时的全部代码,无需逐包替换。
3. 重建后所有账号初始密码 `Yxnsh@1a3s`、`pwd_change_flag=1` 首登强制改密;测试可先 `UPDATE ccr_sys_user SET pwd_change_flag='0'` 跳过。
4. **回滚**:恢复第 0 步备份(重建前为最终一致性快照,重建后仅能恢复到备份时刻)。
5. 全量重建涉及 `db/` 下含敏感种子脚本(`08_system.sql`/`03f_node_assignee.sql`/`23_password_change_flag.sql`/`24_plaintext_sensitive.sql`/`18_contract_operator.sql`),仅本机/生产执行,**禁止 push 到 GitHub**。
