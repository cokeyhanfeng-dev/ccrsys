# 需求文档：审批流程简化 + 审批链路配置人性化

> 状态：用户已核验需求一/二/三口径（2026-08-25 补充），需求四方案待确认，未实施任何代码改动
> 涉及模块：ccr-frontend（loan.vue / deposit.vue / params.vue）、ccr-backend（ccr-application / ccr-approval / ccr-rule）

---

## 需求一：存量授信取消自动拉入拆分，改手工录入；链路按总授信额度匹配

### 现状
1. **存量客户（存量调息）**：利率申请页从数仓**自动拉入授信担保拆分明细**（`creditSplits`，按成员×合同×担保方式拆），默认全选并生成**多个分项卡片**（`selectAllSplits`）；授信概览同时展示"授信总金额（数仓）"与"拆分细项合计（分项求和）"，总授信 = 拆分合计。
2. **集团客户**：按"成员 × 担保项"生成分项。
3. **审批链路金额定档**：后端 `buildRouteInput` 中 `amountBasis = APPLY_AMOUNT`（按**本笔分项申请金额**定档，2026-08-14 调整），即每条分项按自身金额匹配权限矩阵金额档与上会金额条件。

### 目标（用户口径确认）
1. **不再自动拉入**：存量客户不再从数仓自动带出拆分明细、不再自动生成多个分项。
2. **手工录入拆分**：由业务人员**手工录入整个拆分**——自行添加分项（担保方式/产品/期限/金额/利率等）及利率申请内容。
3. **总授信额度** = 手工录入分项的合计（随分项自动同步；新增/存量口径一致）。
4. **审批链路匹配**：金额定档基准改为**总授信额度**口径（存量 = 手工录入分项合计/总授信，集团 = 集团综合授信批复总额度）；整个审批流程均按总授信额度匹配权限矩阵金额档与上会金额条件。

### 预计改动范围
- 前端：移除存量"自动拉入拆分项并默认全选"逻辑（`creditSplits` 自动带出/`selectAllSplits` 不再自动触发），存量也走手工添加分项；授信概览与总授信同步逻辑调整。
- 后端：`ApplicationSubmitServiceImpl.buildRouteInput`、`ApprovalServiceImpl` 中 `amountBasis` 由 `APPLY_AMOUNT` 改为总授信口径，并正确传入总授信额度；矩阵金额匹配与上会金额条件取数同步调整。

### 待核验疑问
- 数仓"授信总金额"是否仍保留作**只读参考展示**（不拆分明细，仅展示总额）？
- 集团手工录入拆分的"成员"维度是否保留（每条分项仍选集团成员）？

## 需求二：分项增加"测算利率"字段（在现有两个利率之上）

### 现状
1. **贷款分项**现有两个利率：原利率（存量带出）+ 申请利率。
2. **存款分项**现有两个利率：当前执行利率 + 申请利率。
3. 均无"测算利率"字段。

### 目标（用户口径确认）
1. 在**现有两个利率的基础上增加第三个"测算利率"字段**，位于分项上。
2. 测算利率由**业务人员手工录入**（所有分项统一支持，不区分能否拉出明细）。
3. 仅录入/展示，不参与链路匹配或利率定价（未另行说明，默认不参与）。

### 预计改动范围
- 前端：loan.vue / deposit.vue 分项模板加"测算利率"输入框（与现有利率同排）；提交数据加字段；审批详情/归档展示透出。
- 后端：提交 JSON 增加字段透传。

### 待核验疑问
- 测算利率是否参与审批表决/链路？（默认：不参与，仅作为申请内容录入展示）
- 是否需要校验（必填/范围）？（默认：选填，与申请利率相同的 0~100 范围兜底）

## 需求三：抵质押物录入区保留、取消强制校验

### 现状
- 前端提交校验：担保方式 ≠ 信用（`guaranteeType !== 'CREDIT'`）时，**必须至少登记一条担保措施明细**（抵押/质押/保证/存单/保证金），否则拦截"请至少登记一条担保措施明细"。
- 分项卡片含抵押物 / 质押物 / 存单质押 / 保证金 / 保证人明细录入区。

### 目标（用户口径确认）
1. **录入区保留**：抵押物/质押物等担保明细录入区**保留在界面上**，不删除。
2. **取消强制校验**：即使担保方式选了**抵押**，也可以选择**不录入**抵质押物信息直接提交。
3. 保留金额非负等数据合理性校验。

### 预计改动范围
- 前端：提交校验中删除"担保措施明细至少一条"的强制（保留非负等合理性校验）。
- 后端：提交/审批侧如有同款强制校验，同步放宽。

### 待核验疑问
- 取消强制的范围默认覆盖**所有非信用担保**（抵押/质押/保证/存单/保证金）？还是仅抵押/质押？（用户表述以抵押为例，默认全部非信用担保取消强制）

## 需求四：审批链路配置人性化 + 自动化（方案待确认）

### 现状
- 配置入口：系统参数 → 产品配置中心 → **产品审批链路** tab。
- 配置字段偏技术化，业务管理员难以理解：
  - 产品编码（下拉）
  - **路由模式**：链式逐级 CHAINED / 直接上会 DIRECT_VOTE（英文编码）
  - **起始节点**：节点编码（如 BRANCH_MANAGER）
  - **强制上会**（六人小组）Y/N
  - **行长决策** Y/N
  - **上会条件**：JSON 构建器（金额档 + 企业类型下拉，生成 `{"amount_tier":"GE_5000","enterprise_type":"SOE"}`），另可手改裸 JSON
  - 优先级 / 生效日 / 备注
- 状态机：DRAFT → PENDING_REVIEW → PUBLISHED → OBSOLETE（发布需双人复核）。
- 后端已向后兼容：未配置链路时按权限矩阵纯驱动。

### 建议方案（待用户确认）
**人性化（看得懂）**
1. 界面白话化：术语改业务用语，每字段带说明（"直接上会"是什么、"强制上会"影响什么、金额档含义）。
2. **上会条件可视化**：不再手写 JSON——用组合式选项（金额档下拉 / 企业类型 / 利率越界开关）构建，实时回显为可读中文描述；JSON 仅作底层面板。
3. **配置可预览**：保存前可"模拟路由/预览实际审批链路"，步骤条展示该产品不同金额、不同客户类型下的实际审批走向，直观确认效果。
4. 新建默认值/推荐：按产品类型（贷款/存款）自动预填合理默认（贷款=链式逐级、起始=支行行长；存款=直接上会），业务大类自动带出。

**自动化（少配置）**
5. **默认链路自动兜底**：产品未配置链路时，自动按业务大类走默认链路（贷款链式逐级、存款直接上会），链路配置不再是必选项。
6. 规则自动推断/提示：如"对公贷款金额 > 5000 万强制上会"类规则，配置时自动提示/推荐勾选强制上会。
7. 配置变更影响预览：发布前显示该链路关联的产品与在途申请，避免误配置。

### 预计改动范围
- 前端：params.vue 链路配置 tab 界面重构（字段说明、条件可视化构建器、默认值、保存前预览）。
- 后端：默认链路统一逻辑、配置校验、试算/预览接口完善。

### 待核验疑问
- 链路配置的实际使用者角色（仅管理员，还是业务人员也配）？
- "上会条件"是否需支持更多维度（目前金额档 + 企业类型）？
- 自动兜底默认链路的参数（各业务大类起始节点 / 是否上会）是否也需要可配置？

## 验收标准（总）
1. 存量客户不再自动拉入拆分项，业务人员手工录入分项（含利率申请内容）；总授信 = 分项合计；审批链路按总授信额度匹配（集团按集团总授信金额）。
2. 贷款/存款分项在现有两个利率基础上增加"测算利率"字段，业务人员手工录入，提交与详情展示透出。
3. 抵押物等担保明细录入区保留，但不再强制校验——选抵押也可不录入抵质押物直接提交。
4. 产品审批链路配置界面：中文白话、字段有说明、上会条件可视化、保存前可预览实际链路；未配置链路时按默认链路自动运行，不再强制配置。
